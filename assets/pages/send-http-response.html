Send HttpResponse

Send HttpResponse is the workflow step that returns data to the HTTP caller. It is used in request-driven flows where the workflow itself is responsible for building the final response.

What it is

This connector reads response settings from the pipeline and writes the final HTTP response back to the caller. It is usually the last visible step in an API-style workflow.

Why it is useful

  • Return success or failure payloads with a controlled status code.
  • Set response headers without writing custom backend code.
  • Close the request cleanly after the business logic finishes.

When you double-click it

Configure the response fields the runtime expects:

  • httpStatusCode - number or string value for the HTTP status.
  • httpStatusMessage - string text for the status message.
  • headerList / headers - a document list of header name and header value pairs.
  • responseBody - string or object payload returned to the caller.

Workflow input and output

  • Input - pipeline values that resolve to status, headers, and body content.
  • Output - the HTTP response side effect; the payload is returned to the caller.

Runtime notes

Keep the body and headers explicit so the caller receives the exact response you expect. This step is commonly paired with Data Transformer and Workflow End.
