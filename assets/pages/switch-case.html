Project / Reusable Service / Switch Case

Route service execution by matching one pipeline value.

SWITCH resolves one expression and compares it with ordered CASE values. It runs the children of the first matching CASE, otherwise it runs the optional DEFAULT branch, then continues after the SWITCH block.

What SWITCH does

Compare one value with several possible cases

Use SWITCH when each branch depends on the same pipeline value, such as status, channel, country, type, or operation name.

PartPurposeExample
SWITCH expressionResolves the value used for every comparison.${pipeline.input.order.channel}
CASEDefines one exact value, substituted value, or regular expression.WEB or /^PARTNER_.+$/
DEFAULTProvides fallback behavior when no CASE matches.Reject or route an unknown channel.
i
Only one branch runs

CASE branches are checked in order. After the first match, its children run and remaining cases are skipped. DEFAULT is considered after every normal CASE. If nothing matches and DEFAULT is absent, SWITCH performs no child work and execution continues afterward.

Add the flow step

Create SWITCH from the reusable service Flow tab

  1. 1
    Prepare the source value

    Make sure the selected value exists in Service Input or is produced by an earlier MAP, utility, or service-call step.

  2. 2
    Select Flow

    Find SWITCH in the reusable service step library.

  3. 3
    Add SWITCH

    Click it or drag it into the intended position in the service tree.

  4. 4
    Set the expression

    Select SWITCH and use the Expression action in Properties.

  5. 5
    Add cases

Switch expression

Select the pipeline value to compare

The expression editor is designed for a pipeline value such as a String, number, Boolean, or another scalar value.

${pipeline.input.order.channel}

${pipeline.output.normalizedStatus}

${pipeline.temp.loopItem.type}

Pipeline substitution is applied before matching. A missing or blank expression resolves to no value; only a matching null case or DEFAULT can handle it.

!
Use IF-ELSE for multiple independent comparisons

SWITCH compares one resolved value. If the decision needs amount ranges combined with status, country, and Boolean flags, use IF-ELSE.

CASE and DEFAULT branches

Add one branch per expected value

  1. 1
    Select SWITCH and click ADD CASE

    A new CASE branch is added and selected.

  2. 2
    Add a Comment

    Describe what the value means to the business.

  3. 3
    Edit Runtime value

    Enter an exact value, a pipeline substitution, or a regex wrapped in forward slashes.

  4. 4
    Repeat for remaining values

    Use Move up/down or drag cases to establish their matching order when patterns can overlap.

  5. 5
    Create the fallback

    Change one branch's Case type from case to default. Its Runtime value is cleared and the UI places it after normal cases.

Use only one DEFAULT branch. Multiple defaults make later defaults unreachable because the first DEFAULT always matches.

Runtime matching

Exact, numeric, null, substituted, and regex cases

Case styleRuntime valueBehavior
Exact textWEBMatches trimmed text without case sensitivity, so WEB also matches web.
Number10Numeric-looking values are compared numerically.
BooleantrueMatches a Boolean true value or its normalized text representation.
Null$nullMatches when the SWITCH expression resolves to null.
Pipeline substitution${pipeline.input.expectedChannel}Resolves the expected value at runtime before comparison.
Regular expression/^PARTNER_[A-Z]+$/Applies a Java regular expression to the complete trimmed SWITCH value.
DEFAULTNot applicableMatches only after no normal CASE matched.
!
Invalid regex fails the service

A malformed value enclosed in /slashes/ raises SWITCH_ERROR. Test regex cases with expected, unexpected, and empty values.

Steps inside cases

Each CASE owns an ordered child flow

CASE and DEFAULT are containers. Only the selected branch's child steps execute.

  1. 1
    Select CASE or DEFAULT

    Choose the branch in the service flow tree.

  2. 2
    Add a child

    Use Add child to create a Map pipeline child, or drag a Flow/Utils step onto the branch and drop it inside.

  3. 3
    Add the branch implementation

    Cases can contain mappings, utilities, project-service calls, loops, TRY/CATCH, process groups, and other supported steps.

  4. 4
    Map each child

    The SWITCH and CASE control items do not expose pipeline mapping. Select executable children to configure their pipeline.

SWITCH  (${pipeline.input.order.channel})
├── CASE  WEB
│   ├── Map pipeline: route = WEB_ORDER
│   └── Project service: validateWebOrder
├── CASE  /^PARTNER_[A-Z]+$/
│   └── Project service: validatePartnerOrder
└── DEFAULT
    └── EXIT: unsupported order channel

Map pipeline: build final response

The final MAP step is outside SWITCH, so it runs after the selected case finishes.

Good practices

Keep case routing predictable

  • Use a scalar and stable pipeline value as the SWITCH expression.
  • Add Comments that explain the business meaning of SWITCH and every CASE.
  • Place exact values before broad regex patterns when both could match.
  • Use anchors such as ^ and $ to make regex intent clear.
  • Keep one DEFAULT branch and use it for safe fallback or explicit rejection.
  • Use IF-ELSE when branches depend on different fields or numeric ranges rather than one value.
  • Keep side effects inside cases intentional because only one case executes.
  • Test exact case, case-insensitive text, regex, null, blank, unknown, and DEFAULT behavior.
