Workflow triggers / Salesforce

Start a workflow from Salesforce events.

Salesforce Trigger subscribes to an event channel through a project Salesforce Connection, then places each accepted event in the workflow pipeline. Change Data Capture and platform events use Pub/Sub API; Generic and PushTopic events use Streaming API.

Design

Add and configure the trigger

  1. 1
    Create a Salesforce Connection

    Follow the connection guide; test and enable it.

  2. 2
    Add Salesforce Trigger

    Open a workflow, drag Salesforce Trigger from Workflow triggers, and connect it to the first processing step. A workflow has one trigger.

  3. 3
    Choose connection and event type

    Double-click the trigger. Select the project Salesforce connection. Choose an event type, then enter the exact case-sensitive object, event, or channel name.

  4. 4
    Choose replay and verify

    Select a replay starting point and click Check subscription. Save the workflow, resolve any warnings, and enable it. Check the Runtime status before publishing a test event.

Verification

Use Check subscription before testing the workflow

The button checks the selected channel with the configured credential. Pub/Sub types verify that the topic exists and is subscribable. Generic and PushTopic types perform a Streaming API handshake and subscription, then disconnect. It does not publish an event or start a workflow. A successful check proves channel subscription at that moment; the workflow must still be saved and enabled to receive events.

Examples: a missing Generic channel can report an unknown channel; insufficient permission can report access denied; 403::Unknown client means the CometD session was lost. Kestrel retries a failed running subscription. If the error persists, check the Runtime status and application logs.

The example shows the shape of a Generic event; do not rely on a particular replayId value or assume Pub/Sub events contain the same fields.

Continuity

Choose where subscription starts

Replay fromBehavior
New eventsStart with events published after subscription when no saved cursor exists.
Earliest retained eventStart at the earliest Salesforce event still available when no saved cursor exists.
Specific replay IDStart at a supplied cursor. Streaming API requires a numeric ID; Pub/Sub API requires a Base64 replay ID.

Kestrel saves the last admitted replay position and resumes after a restart. Salesforce retains events only for a limited period; an expired replay ID requires choosing a new start position. Treat delivery as potentially repeated and design downstream effects to be idempotent.

Operations

Read Runtime and application logs

The trigger shows connecting, connected, or retrying and a next retry time when available. Subscription success, failure, and recovery are written to kestrel-application-logs and can be viewed in OpenSearch. Search for salesforce-trigger, the workflow ID, or the channel. Workflow run data belongs in execution analytics; a subscription error can happen before any run exists.

To test Generic Event delivery, first make sure /u/TestGenericChannel exists in Salesforce, check the subscription, enable the workflow, then publish a Generic notification to that channel using Salesforce's Streaming Channel Push REST API. Merely inserting a StreamingChannel creates the channel and does not publish a notification.
