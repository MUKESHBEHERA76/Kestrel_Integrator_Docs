Logger

Logger is the workflow step that writes a runtime message without changing the main payload. It is the simplest way to trace what a pipeline is doing while it runs.

What it is

The logger step reads pipeline values and writes them to the runtime log stream. In Kestrel it is stored as a workflow utility, not as an external service call.

Why it is useful

  • Track branch decisions and execution progress.
  • Print important values for support and debugging.
  • Leave a readable audit trail during test runs or production incidents.

When you double-click it

Open the step configuration and map the three fields the runtime expects:

  • logMessage - string value to write to the log.
  • function - string label for the logical function or step name.
  • level - string severity such as info, warn, or error.

Workflow input and output

  • Input - pipeline values, usually strings or resolved expressions.
  • Output - no payload output; the effect is the runtime log entry.

Runtime notes

Logger is best used when you need a quick checkpoint in the flow. It does not call an external system and it should not be used to store business data.
