Security prerequisite

Obtain and verify Known Hosts content

Ask the SFTP administrator for the host-key fingerprint over a trusted channel. Retrieve the public host key from the endpoint:

ssh-keyscan -p 22 sftp.example.com > sftp_known_hosts
ssh-keygen -lf sftp_known_hosts -E sha256

Compare the displayed SHA-256 fingerprint with the administrator’s value before using the file. ssh-keyscan alone does not authenticate the server. The file contains complete lines like sftp.example.com ssh-ed25519 AAAA...; use the full Base64 key, not the fingerprint, in Known Hosts content. For port 2222, the hostname token is normally [sftp.example.com]:2222. Do not paste a private login key here.

Go to Security → Security Credentials, create type Known Hosts (SSH), set alias SFTP_PRODUCTION_KNOWN_HOSTS, paste the verified file content, and save it. The full SFTP guide shows each step and example output.

Project connection

Enter endpoint and authentication

Open Projects → your project → Connections → Create Connection → SFTP. Example: name Production SFTP, host sftp.example.com, port 22, username sftp-user, default remote directory /data/inbound, and host verification alias SFTP_PRODUCTION_KNOWN_HOSTS. Choose password, private key, or both as required by the server. For private-key login, select the login key from Security → Keystore; this is separate from the server host key.

Test the connection before saving. The test checks host identity, login, SFTP negotiation, and the configured base directory. Save and enable the connection, then select it in the SFTP connector. The field reference covers timeouts, size limit, fingerprint pinning, and authentication options.

Client login

Choose the authentication method

Password shows and requires Password. Private key shows SSH private key alias and optional passphrase; the corresponding public key must be authorized for the remote account. Password and private key requires both the password and the SSH key alias. In the current application, the SSH private key dropdown reads entries from Security → Keystore, not Security Credentials. Use Create SSH Key or Add SSH Key there, then reopen the SFTP form if the new alias is not shown. The Known Hosts credential is a different item: it verifies the server, not the client login.

Server identity

Configure mandatory host verification

For Known Hosts credential, create a Known Hosts (SSH) Security Credential and choose its alias. See the keyscan and fingerprint walkthrough above. For Pinned SHA-256 fingerprint, obtain the fingerprint independently from the server owner and enter the exact SHA256:... value. Host verification cannot be disabled. If a server rotates its host key, verify the new key before updating either value.

Validation

Test, save, and use the connection

Click Test connection after setting the endpoint, login, host verification, and base directory. This checks that Kestrel can open SFTP and access the configured directory. Save and enable the connection, then select it in the workflow SFTP connector. A later Upload or Delete may still fail if the account lacks that operation's permission. The operation reference describes each workflow action.
