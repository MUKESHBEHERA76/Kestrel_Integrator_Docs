Project model

Projects

In Kestrel Integrator, a project is the package of artifacts for one integration solution. It is the top-level workspace that keeps workflows, reusable services, connections, APIs, data structures, XSLT aliases, schedulers, and console activity under one project ID.

What is a project?

A project is the context that drives the tool. When you select a project, the UI loads the correct workspace, the designer uses the correct project scope, and the console or monitor pages stay aligned with that same project.

What lives inside a project?

  • Workflow - the orchestration flow that connects steps, mappings, runtime variables, and execution logic for the project.
  • Reusable services - shared service flows that can be called from multiple workflows inside the same project.
  • API - project-scoped endpoints used to expose or consume business data.
  • Connections - reusable database or security connectors that the project uses in workflows, services, and console execution.
  • Data Structure - the input, output, and document shape definitions used while designing mappings and steps.
  • XSLT Alias - the alias names used to support transformation logic inside the project.
  • Schedluer - the scheduler setup that triggers project workflows automatically at the configured time.

Why is a project needed?

  • Scoped assets - each integration asset stays attached to the selected project only.
  • Correct runtime context - the designer, console, and monitor all use the same project scope.
  • Clear ownership - teams can see exactly which solution a workflow, service, or connection belongs to.
  • Project identity - every project has its own backend ID, so routes and saved data always resolve to the right project.
