Project / Reusable Service

Build shared integration logic once and call it where needed.

A reusable service is a project-scoped flow with a defined input and output contract. It contains mapping, utilities, control flow, and calls to other project services without owning a webhook or scheduler trigger.

Reusable Service concept

A callable unit of project logic

Use a reusable service when multiple workflows or services need the same transformation, validation, calculation, lookup, or business rule.

The caller supplies values defined by the service input contract. The service executes its ordered flow steps and returns values defined by its output contract. This keeps shared behavior in one place and prevents developers from rebuilding the same mapping or utility sequence in multiple workflows.

WorkflowReusable Service
Starts from one Webhook, Scheduler, or SubWorkflow trigger.Has no trigger. It starts when a workflow, another service, or the Run action invokes it.
Describes an end-to-end integration topology.Packages a focused piece of shared logic.
Uses a node canvas connected by arrows.Uses an ordered, hierarchical flow tree.
Can use workflow-only connectors such as HTTP Request.Uses flow steps, built-in utilities, and calls to project services.
Can be enabled or disabled for operational control.Has no enable/disable state; a saved reusable service can be run or called.

Service I/O

Define the contract before implementing the flow

Select Service I/O in the editor header to define what callers provide and what the service returns.

Contract areaPurposeExample
InputValues required from the caller.${pipeline.input.customerId}
OutputValues returned after the service finishes.${pipeline.output.customerStatus}

Contract fields can use String, String List, Document, Document List, and the other supported variable types. Documents can define nested fields or reference an existing project Data Structure. Use clear names because callers see this contract in their pipeline mapper.

!
Treat contract changes as integration changes

Renaming or removing an input/output can break mappings in workflows and services that already call this service. Review callers after changing the Service I/O contract.

Flow tab

Control execution with ordered and nested steps

The Flow tab provides structure and control logic. Containers can own child steps in the flow tree.

Flow stepWhat it does
Map pipelineCopies, transforms, hardcodes, drops, or creates values in the service pipeline.
IF / ELSERuns the first branch whose pipeline-based condition matches. Optional ELSE IF and ELSE branches can be added.
LOOPIterates a String List, Document List, or other supported list variable and runs its child steps for each item.
SWITCHEvaluates one expression and routes execution to matching case or default branches.
Process GroupGroups related child steps to keep a larger service organized.
TRY / CATCH / FINALLYHandles step failures. CATCH receives error information; FINALLY performs cleanup after TRY/CATCH.
EXITStops the current loop or the complete service. It can optionally raise an exception with a pipeline-substituted error message.

The handbook icon in the editor header provides short in-product guidance for these flow steps.

Utils tab

Use built-in operations and other project services

The Utils tab contains the utility catalog and available project reusable services. See the complete Utils reference for each built-in operation's input/output contract and examples.

  • Built-in utilities — String, Math, Date, JSON, XML, List, Hashtable, KVS, and Flow operations.
  • Project services — saved reusable services from the current project that can be invoked as service-call steps.
  • Search — filter by utility, service, or group name before adding the step.
  • Utility help — inspect the utility inputs, behavior, and output while designing the service.

After adding a utility or service call, select it and use the Pipeline panel to supply its inputs and retain its outputs.

Service Pipeline

Move data through each selected step

The service pipeline uses the same typed mapping model as workflow steps.

Pipeline actionUse
MapConnect an available pipeline value to a selected step input, or connect the step result to pipeline output.
HardcodeProvide a fixed String, Boolean, String List, Document, Document List, or JSON-compatible value.
Runtime variableCreate a new output variable, including nested structures, for later service steps.
CopyCopy the selected normalized pipeline expression for use in conditions, messages, or hardcoded substitutions.
Drop / UndropRemove an unwanted branch from the pipeline or restore it.
List index mappingMap a complete list or a selected list item using a fixed or pipeline-provided numeric index.

See Pipeline Sub for String, String List, Document, and Document List syntax and copy instructions.

Build sequence

A simple way to create a reusable service

  1. 1
    Define Service I/O

    Create the smallest clear input and output contract needed by callers.

  2. 2
    Add flow structure

    Add Map pipeline, conditions, loops, error handling, or process groups in execution order.

  3. 3
    Add utilities and project services

    Use the Utils tab for the transformations and shared operations required by the implementation.

  4. 4
    Order and nest steps

    Move or drag steps in the tree. Indent steps inside LOOP, IF, SWITCH, TRY/CATCH, or process-group containers.

  5. 5
    Configure properties

    Select every step and define its condition, source list, case value, exit behavior, or service target.

  6. 6
    Map the pipeline

    Supply every required Step In value and place the final results into the Service I/O output paths.

  7. 7
    Run or debug

    Test representative input, inspect step behavior, and correct mappings before saving the final design.

  8. 8
    Save

    Persist the reusable service so workflows and other services can discover its current contract.

Calling a service

Invoke it from a workflow or another reusable service

Saved project services appear as callable items in the caller's palette.

  1. 1
    Open the caller

    Edit a workflow or another reusable service in the same project.

  2. 2
    Find the project service

    Use the Utils/service palette search and add the reusable service as a service-call step.

  3. 3
    Map the service input

    The caller sees the saved Service I/O input fields. Map its pipeline values to those fields.

  4. 4
    Map the service output

    Place returned values into the caller's pipeline for downstream steps.

i
Calls are project-scoped

The service palette resolves reusable services from the current project. Use unique, descriptive names so developers select the intended service.

Run, debug, and operations

Test the service independently

A reusable service does not need to be enabled before it can run.

  • Run — execute the reusable service with test input and inspect the result.
  • Debug — follow execution step by step and identify the currently executing flow-tree item.
  • Save — persist changes before expecting callers to use the updated contract or implementation.
  • No enable/disable state — every valid saved reusable service is callable.
  • Execution history — reusable service executions appear in the monitoring experience for troubleshooting.
!
A reusable service has no external trigger

Use a workflow when the integration must start from a webhook or scheduler. The workflow can then call the reusable service for its shared implementation.
