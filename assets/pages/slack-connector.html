Workflow setup

Add and configure Slack

  1. Create and test a Slack Connection in the project; grant the Slack app the scopes for the intended operation.
  2. In the workflow editor open Connectors, drag Slack onto the canvas, then connect the preceding and following steps.
  3. Double-click Slack, select the project Connection and an Operation, add an optional comment, and choose Done.
  4. Open its pipeline settings. Map the listed Slack_Request fields from prior step output or runtime variables. Map Slack_Response fields onward, then save the mapping and workflow.

Changing the action changes its input/output contract and clears the previous step mapping. Reopen Pipeline settings and remap fields after any action change. The connection must be enabled when the workflow runs.

Pipeline contract

Read and map request and response documents

Every action has a Step In document Slack_Request containing the fields shown below. Every action has a Step Out document Slack_Response with body, the complete JSON response returned by Slack. Actions with convenient named fields expose those under Slack_Response as listed below. If Slack omits a field, it is absent from the runtime response. Map only the fields needed by the next step.

Slack_Request.channel = "C0123456789"
Slack_Request.text = "Deployment completed"

Slack_Response.ts = "1712345678.000200"
Slack_Response.body = "{\"ok\":true,...}"

For Post message, supply at least text or blocks in addition to channel. blocks and attachments are String inputs containing JSON arrays. Kestrel parses each array before calling Slack. Slack user lists use a single comma-separated string. Slack IDs and message timestamps should be preserved as strings.

Pipeline types: Boolean options such as reply_broadcast and is_private are String fields; enter true or false. limit is a String containing a whole number such as 100. Kestrel validates and converts these values before calling Slack. Response objects and arrays, including message, channels, and body, are JSON Strings for mapping and substitution. members is a StringList of user IDs. To use nested JSON values, parse the response String in a subsequent step.

Dynamic message content

Build blocks and attachments as JSON strings

For Post message, Update message, and Respond to button click, map Slack_Request.blocks or Slack_Request.attachments as a String containing a JSON array. You can hardcode the JSON text or use pipeline variable substitution inside it. Kestrel parses the completed string and sends an array of objects to Slack; an invalid JSON array enters workflow error handling with the field name. An empty array [] is allowed. Existing workflows that map an actual document list continue to work.

Post message example: Suppose ${pipeline.input.deploymentStatus} is Ready and ${pipeline.input.statusColor} is #2eb67d. Enter these strings in the two pipeline fields:

Slack_Request.blocks = [{"type":"section","text":{"type":"mrkdwn","text":"*${pipeline.input.deploymentStatus}*"}}]
Slack_Request.attachments = [{"color":"${pipeline.input.statusColor}","text":"Build 42"}]

At runtime, the resulting arrays contain "text":"*Ready*" and "color":"#2eb67d". For arbitrary dynamic text, ensure the substituted content is JSON-safe: quotes, backslashes, and line breaks inside a JSON string must be escaped. A prior transformation can produce the complete JSON array string when the structure varies by run. Do not map a JSON object alone; these fields require an array.

Update message: map Slack_Request.channel and Slack_Request.ts, then use the same JSON strings in blocks or attachments. Respond to button click: map the interaction's response_url, then use the same fields for the response message. See Slack's chat.postMessage, chat.update, and interaction response guides for supported block and attachment shapes.

Developer examples

End-to-end mappings

Notify a deployment channel

Choose Post message and map Slack_Request.channel to C0123456789, Slack_Request.text to a prior step’s deployment summary, then save Slack_Response.ts to update or thread the message later. Parse the JSON String in Slack_Response.body to inspect its ok property.

Create and populate a private project channel

Use Create conversation with name=launch-2026 and is_private=true. Parse id from the JSON String in Slack_Response.channel; that value becomes Slack_Request.channel for Invite users, with users=U0123456789,U9876543210. Post a welcome message in a later Slack step.

Respond to a button click

Configure a Webhook Trigger to receive Slack’s interactivity form post. Slack places the interaction JSON in the form field payload. Parse that string into a document with the JSON-to-document utility, then map its response_url to Slack_Request.response_url; set text=Approved and response_type=ephemeral. Respond to Slack’s inbound request promptly using Send HttpResponse. Authenticate Slack’s signed inbound request at a trusted ingress; this outgoing connector’s response URL check does not verify the incoming signature.

Runtime behavior

Handle failures in the workflow

Missing required fields, disabled or missing connections, HTTP failures, Slack ok:false responses, and invalid interaction URLs raise connector errors. Connect the workflow’s error handling path to inspect the exact Slack error, log useful context without tokens or response URLs, and decide whether to retry. Slack rate limits may include a Retry-After delay. Avoid blind retries for actions such as creating a channel or posting a message because a retry can duplicate side effects.

The connection test calls auth.test; it does not verify every operation’s scopes, conversation membership, or message permissions. Run representative workflow operations with the intended Slack app installation before production use.
