Connector / HTTP Request

Call REST, GraphQL, and SOAP APIs from a workflow.

HTTP Request is a workflow-only connector. Its configurator selects the API type; its pipeline supplies the URL, headers, authentication, request data, timeout, and protocol-specific values at runtime.

Getting started

Add and configure the connector

HTTP Request is available in the Workflow Editor and is intentionally not available in the Reusable Service Editor.

  1. 1
    Open a workflow

    Drag HTTP Request from the HTTP Request connector category onto the workflow canvas.

  2. 2
    Open the configurator

    Double-click the step. Connector name is read-only; Comment is editable.

  3. 3
    Select API Type

    Choose REST, GraphQL, or SOAP. The workflow cannot be saved while the API type is missing.

  4. 4
    Open pipeline settings

    Select the step and use its settings icon. The Step In fields change to match the selected API type.

  5. 5
    Map deliberately

    Connect pipeline values or hardcode only the intended fields. HTTP Request does not automatically copy incoming fields into headers or other inputs.

  6. 6
    Map the response

    Map statusCode, responseHeaders, and responseBody to the pipeline output fields needed by later steps.

!
Changing API Type changes the Step In contract

Review mappings after switching between REST, GraphQL, and SOAP because protocol-specific inputs are rebuilt for the selected type.

Common pipeline contract

Inputs available for every API type

Every field supports mapping from the workflow pipeline. Strings inside mapped documents and lists also support pipeline substitution.

Step In fieldTypeRequiredRuntime behavior
urlStringYesAbsolute target endpoint. Query parameters are appended after URL encoding.
headersDocumentNoExplicit request headers only. Nothing from the incoming webhook or previous step is copied automatically.
queryParamsDocumentNoKey/value query parameters. Existing query text in the URL is preserved.
timeoutMillisString/numberNoPositive integer in milliseconds. Default is 30,000 ms. One deadline covers OAuth token retrieval and the API call.
authenticationDocumentNoOptional structured authentication settings described below.
i
Map, hardcode, or substitute

An exact expression such as ${pipeline.input.endpoint} keeps the original value type. Embedded expressions such as https://api.example.com/users/${pipeline.input.userId} are substituted into the surrounding string. The same recursive substitution applies inside headers, query parameters, authentication, GraphQL variables, form fields, and attachment documents.

Authentication document

Build authorization at runtime

Map credentials from secure pipeline values. Do not log authentication fields or hardcode production secrets in the workflow definition.

authTypeFields usedWhat the connector sends
NONENoneNo generated Authorization header. This is also the default when authType is empty.
BASICusername, passwordAuthorization: Basic <base64(username:password)>
BEARERbearerTokenAuthorization: Bearer <token>
OAUTH2_CLIENT_CREDENTIALStokenUrl, clientId, clientSecret; optional scope, audienceCalls the token endpoint using a form-encoded client-credentials request, then sends the returned token type and access token in Authorization.
!
API keys are explicit values

Place an API key directly in headers using the provider's required header name, or in queryParams when the provider explicitly requires a query key. No API key is added automatically.

API Type: REST

Send standard HTTP requests and raw bodies

REST adds method, requestBody, formFields, and attachments to the common inputs.

FieldTypeDescription
methodStringGET, POST, PUT, PATCH, DELETE, HEAD, or OPTIONS. Default is GET.
requestBodyStringRaw payload sent as UTF-8. It can contain JSON, XML, text, or another format understood by the API.
formFieldsDocumentText parts used only when the explicitly mapped Content-Type starts with multipart/form-data.
attachmentsDocument ListBinary multipart parts supplied as Base64 or bytes from the pipeline.
 
url: https://api.example.com/orders
method: POST
headers:
  Content-Type: application/json
  Accept: application/json
requestBody: |
  {"customerId":"${pipeline.input.customerId}","amount":125.50}
timeoutMillis: 15000

The connector does not infer a body format. Set the matching Content-Type explicitly in headers.

API Type: GraphQL

Use one field for queries and mutations

GraphQL always uses POST. The connector builds a JSON envelope containing query and variables and defaults Content-Type to application/json.

FieldTypeDescription
graphqlQueryStringRequired GraphQL query or mutation text. Mutations are entered here, not in requestBody.
graphqlVariablesDocumentVariables object. It may be mapped as a document or entered as valid JSON text.
 
graphqlQuery:
  mutation CreateUser($name: String!, $email: String!) {
    createUser(name: $name, email: $email) {
      id
      name
      email
    }
  }

graphqlVariables:
  {
    "name": "${pipeline.input.name}",
    "email": "${pipeline.input.email}"
  }

The transmitted body is equivalent to {"query":"mutation ...","variables":{"name":"...","email":"..."}}.

API Type: SOAP

Send a complete SOAP XML envelope

SOAP always uses POST. Supply the final XML envelope in requestBody; the connector does not import a WSDL or generate an operation payload.

FieldRequiredDescription
soapVersionNo1.1 by default, or 1.2.
soapActionService-dependentFor SOAP 1.1 it becomes the SOAPAction header. For SOAP 1.2 it is added as the Content-Type action parameter.
requestBodyYesComplete SOAP XML envelope as a String. Pipeline expressions can be embedded in the XML.
 
url: https://www.dataaccess.com/webservicesserver/NumberConversion.wso
soapVersion: 1.1
soapAction: https://www.dataaccess.com/webservicesserver/NumberToWords
requestBody: |
  <?xml version="1.0" encoding="utf-8"?>
  <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
    <soap:Body>
      <NumberToWords xmlns="http://www.dataaccess.com/webservicesserver/">
        <ubiNum>${pipeline.input.number}</ubiNum>
      </NumberToWords>
    </soap:Body>
  </soap:Envelope>

REST multipart requests

Send text fields and pipeline-supplied attachments

Multipart is a REST body format, not an API type. Activate it by explicitly mapping Content-Type: multipart/form-data in headers.

Attachment fieldRequiredDescription
fieldNameNoMultipart form field name. Defaults to file.
fileNameYesFilename included in Content-Disposition.
contentTypeNoFile media type. Defaults to application/octet-stream.
contentBase64One content fieldBase64-encoded content from the pipeline.
contentBytesOne content fieldByte array or numeric byte list from the pipeline. Takes precedence over contentBase64.
 
method: POST
headers:
  Content-Type: multipart/form-data
formFields:
  description: Monthly report
attachments:
  - fieldName: file
    fileName: report.pdf
    contentType: application/pdf
    contentBase64: ${pipeline.input.reportBase64}

Kestrel generates the multipart boundary and replaces the Content-Type value with multipart/form-data; boundary=....

Step Out contract

Receive the response without forced parsing

The connector returns transport-level results for every API type. Parse or map the response explicitly in later workflow steps.

Step Out fieldTypeDescription
statusCodeIntegerHTTP response status such as 200, 404, or 500.
responseHeadersDocumentResponse header map. A header with one value is a string; repeated values are returned as a list.
responseBodyStringRaw response decoded using the response charset; UTF-8 is used when none is declared or the charset is invalid.
i
HTTP error statuses are still responses

A 4xx or 5xx response is returned through statusCode, responseHeaders, and responseBody. Use workflow logic to decide which status codes are acceptable. Transport, timeout, and configuration failures raise connector errors.

Runtime and operational behavior

Timeouts, redirects, headers, and failures

These details are important when troubleshooting production integrations.

Timeout deadline

timeoutMillis must be positive. The remaining time is recalculated across OAuth2 token acquisition, connection, and response waiting.

Redirects

The Java HTTP client follows normal redirects. The final response is returned to the pipeline.

Explicit headers only

Inbound webhook and previous-step headers do not flow into the outbound request unless the developer maps them intentionally.

Restricted headers

Transport-controlled headers are ignored, including Host, Content-Length, Connection, Expect, Transfer-Encoding, Upgrade, HTTP/2 pseudo-headers, and related hop-by-hop headers.

Interrupted execution

An interrupted request restores the Java thread interruption flag and raises HTTP_REQUEST_INTERRUPTED.

Raw output

JSON, XML, GraphQL, SOAP, text, and error bodies remain strings so the workflow can choose its own parsing and data structure mapping.

Error codeMeaningTypical cause
HTTP_REQUEST_CONFIGURATION_ERRORThe request cannot be constructed.Missing URL/query/XML, invalid timeout, invalid Base64, unsupported method/auth type, or malformed GraphQL variables.
HTTP_REQUEST_TIMEOUTThe configured deadline expired.Slow token endpoint, connection, or remote API.
HTTP_REQUEST_INTERRUPTEDThe execution thread was interrupted.Runtime shutdown or cancellation.
HTTP_REQUEST_ERRORThe HTTP operation failed.Invalid URI, network/DNS/TLS problem, or I/O failure.
HTTP_OAUTH_ERROROAuth2 token retrieval failed.Non-2xx token response, invalid token JSON, or missing access_token.
!
Protect credentials and sensitive responses

Map secrets only into the field that needs them. Avoid Logger and Pipeline Logger for Authorization values, tokens, passwords, client secrets, attachment content, and sensitive response bodies.
