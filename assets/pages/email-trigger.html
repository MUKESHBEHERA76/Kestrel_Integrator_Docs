Workflow triggers / Incoming email

Start a workflow when matching email arrives.

Email Trigger polls a project IMAP or POP3 mailbox, evaluates optional conditions, and starts one workflow run for each matching message. Its pipeline document includes addresses, bodies, headers, and attachments.

Design

Connect a mailbox to the workflow

  1. 1
    Create the incoming connection

    Follow the Email (IMAP/POP3) connection guide. Test mailbox access and leave the connection enabled.

  2. 2
    Add Email Trigger

    Drag Email Trigger from Workflow triggers. Connect it to the first workflow step.

  3. 3
    Choose start position and interval

    Double-click the trigger. Select the connection, choose New mail from activation or Mail received after a date, and set polling to 30–3600 seconds (300 by default).

  4. 4
    Add optional conditions and an action

    Match all or any conditions. Choose what happens to a message only after successful processing. Save, resolve warnings, and enable the workflow.

New mail from activation establishes a mailbox baseline so existing messages are skipped. Mail received after a date scans messages with a received timestamp at or after the UTC value you provide.

With All, every condition must match; with Any, one match is sufficient. With no conditions, every eligible new message qualifies. Filtered messages are recorded and do not start a workflow run.

Field under emailTypeMeaning
uid, messageId, folderStringStable mailbox message identity, Message-ID header, and source folder.

from, to, cc, replyToString eachOne address or multiple comma-separated addresses; empty string when absent.
receivedAtStringUTC ISO 8601 received timestamp when available.
textBody, htmlBodyStringPlain-text and HTML MIME alternatives.
headersDocumentMessage header names to lists of header values.
hasAttachmentsBooleanWhether any attachments were extracted.
sizeNumberServer-reported message size in bytes.
attachmentsDocumentListEach item has fileName, contentType, size, and contentBase64.

Open the trigger's settings to map these values into downstream step inputs. File content is Base64 so binary types such as PDF, DOCX, and images can travel through the pipeline. Current extraction limits are 10 MB per attachment, 20 MB across attachments, and 2 million characters per body alternative; oversized or unreadable messages are rejected and do not start a run.

The action runs after the workflow reports success. Failed or terminated runs leave the mailbox message unchanged. A failed mailbox action is recorded separately for investigation; it does not mean the workflow was rerun.

Example

Handle invoices with attachments

Create an IMAP connection to INBOX, select New mail from activation, poll every 300 seconds, and require Subject contains Invoice plus Has attachments is Yes. Map the first attachment's filename and Base64 content into a downstream storage or Send Email step. Choose Move to folder: Processed after success.

Operational behavior

Understand polling and duplicate protection

Only enabled workflows with an enabled connection are polled. The runtime stores a mailbox cursor and processed-message record; IMAP uses UID validity and UID, while POP3 requires stable UIDL values. A durable run uses a stable message-based idempotency key so the same recorded message is not admitted twice after a retry or restart.

If connection login, folder access, or polling fails, the runtime logs the failure and retries on a later poll. Check workflow execution history for processing failures and backend logs for polling or mailbox-action errors. Configure an Exception Handler path for workflow step failures.
