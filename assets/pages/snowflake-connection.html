Project connection

Set account and session context

  1. 1
    Create the required security entry

    For Basic, create a User Credentials entry with the Snowflake username and password. For Key-Pair, create or import a Keystore key-pair entry and register its public key with the Snowflake user.

  2. 2
    Open Connections

    Go to Projects → your project → Connections → Create Connection → Snowflake. Enter a unique name, such as SnowflakeAnalytics.

  3. 3
    Enter account details

    Enter Account Identifier, Warehouse, Database name, Role, and Schema. The account identifier can be the Snowflake account identifier or full Snowflake host. The selected user must have permission to activate all four session objects.

  4. 4
    Select authentication

    Choose Basic or Key-Pair Auth and select the corresponding alias. Add optional JDBC properties if your environment needs them.

  5. 5
    Connect and save

    Use the connection action to establish a JDBC session and verify role, warehouse, database, and schema. Save the project connection and keep it enabled.

Basic authentication

Select a User Credentials alias

Create an entry in Security → Security Credentials with type User Credentials, for example alias snowflake_analytics_user, username KESTREL_APP, and the Snowflake password. In the connection form, choose Basic and select that alias. The username and password are resolved from the credential when JDBC opens; the connection stores the alias reference.

Key-pair authentication

Select a Keystore alias

Create or import an RSA key pair in Security → Keystore. Snowflake must know the corresponding public key for the chosen user. In the connection form choose Key-Pair Auth, enter the Snowflake username, and select the Keystore key-pair alias, for example snowflake_app_key. Kestrel resolves the private key at runtime; the connection does not require pasted PEM content.

Example: Username KESTREL_APP, key-pair alias snowflake_app_key, and the same account, warehouse, database, role, and schema as above. If Snowflake rejects the login, verify that the public key registered for KESTREL_APP matches the selected Keystore private key.

Advanced JDBC options

Add other driver properties only when needed

Use Other JDBC properties → Add property for additional Snowflake JDBC driver name/value pairs. For example, CLIENT_SESSION_KEEP_ALIVE = true. Each name must be unique and use letters, digits, or underscores, beginning with a letter. Kestrel reserves user, password, privateKey, authenticator, warehouse, db, role, schema, and its result-format setting; secret-like property names are also blocked. Manage authentication through aliases instead.

Properties are passed to JDBC when the connection opens. Check Snowflake driver guidance before setting an option and test again after changing one. Existing connections with embedded password or PEM key continue to run; select an alias when editing them to migrate to the new model.

Validation and troubleshooting

What the connection test proves

The test opens a Snowflake JDBC connection and executes session activation for the configured role, warehouse, database, and schema. It then reads the current session context and checks that those values match. This verifies more than network reachability, but it does not validate every future SQL statement.
