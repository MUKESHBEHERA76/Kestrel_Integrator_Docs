Workflow step

Configure the transformer

  1. 1
    Create the alias

    Follow Projects → XSLT Alias and save a stylesheet in the same project.

  2. 2
    Add the connector

    Drag XSLT transformer from the Connector tab into the workflow and wire it between the source and next step.

  3. 3
    Select the alias

    Double-click the connector and choose the saved alias. The editor stores its ID and name; the runtime resolves it within the workflow's project.

  4. 4
    Map and save

    Open Settings. Map an XML String from the previous step into inputXML; map transformedOutput to the next step. Save the mapping and workflow.

Pipeline contract

One String input and one String output

VariableTypeMeaning
${pipeline.input.inputXML}StringRequired well-formed source XML.
${pipeline.output.transformedOutput}StringSerialized XML produced by the stylesheet.

The connector does not automatically turn a Document into XML. If the source is a Document, serialize it with an XML utility first, then map that String to inputXML. If the next step expects a Document, parse the output XML there. A custom target path can also receive the result, while the default transformedOutput remains available.

Worked example

Transform an incoming order

Choose alias OrderToPurchaseOrder from the alias example. Map the prior step's XML body to ${pipeline.input.inputXML}:

<order><id>ORD-1042</id><total>89.50</total></order>

The XSLT Alias contains:

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="2.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:output method="xml" indent="yes"/>
  <xsl:template match="/order">
    <purchaseOrder>
      <orderNumber><xsl:value-of select="id"/></orderNumber>
      <amount><xsl:value-of select="total"/></amount>
    </purchaseOrder>
  </xsl:template>
</xsl:stylesheet>

After execution, ${pipeline.output.transformedOutput} contains XML equivalent to:

<purchaseOrder><orderNumber>ORD-1042</orderNumber><amount>89.50</amount></purchaseOrder>

Map that output to an HTTP Request body, SFTP upload input, or another XML-aware step.

Runtime

Handle missing input and transform failures

The step fails if no alias is selected or accessible, inputXML is empty, the XML is malformed, or the stylesheet fails to compile or run. Connect an Exception Handler if the workflow should send a controlled response. The runtime disables external stylesheet resources and external protocol access. The stylesheet is limited to 1 MiB and source XML to 5 MiB; large transformations should be designed with those limits in mind.

Because the alias is resolved at runtime, test dependent workflows after editing it. The step returns XML text; its exact whitespace and declaration are controlled by serialization, so validate the XML structure rather than comparing raw strings.
