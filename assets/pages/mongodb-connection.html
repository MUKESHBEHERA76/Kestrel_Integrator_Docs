Project setup

Create and test the connection

  1. 1
    Create a credential, if required

    In Security → Security Credentials, create a User Credentials entry with a MongoDB database username and password. Example alias: mongo_orders_app. This is the database user's credential, not an Atlas web-console login.

  2. 2
    Open the connection form

    Go to Projects → your project → Connections → Create Connection → MongoDB Connection. Enter a unique connection name, for example MongoOrders.

  3. 3
    Enter endpoint and database

    Choose Host and port for a server address, or Atlas DNS SRV for an Atlas seed-list hostname. Enter the host and database name. SRV does not use a port in this form and automatically uses TLS.

  4. 4
    Select authentication and TLS

    Choose Username / password (SCRAM) and select the User Credentials alias, or choose None for a server intentionally configured without authentication. Set the authentication database (often admin). If the server uses a private CA, select a trusted certificate from Security → Keystore while TLS is enabled.

  5. 5
    Test and save

    Click Test connection. Kestrel opens a MongoDB client and runs ping against the configured database. Save after a successful test, keep the connection enabled, and select it in the MongoDB workflow step.

Worked configurations

Standard server and Atlas SRV

Internal MongoDB: Name MongoOrders, Host db.internal.example, mode Host and port, Port 27017, Database orders, Authentication Username / password (SCRAM), alias mongo_orders_app, Authentication database admin, Replica set rs0 if required, TLS enabled, certificate alias mongo_private_ca if the server uses your private CA.

Atlas: Name MongoAtlasOrders, Host cluster0.example.mongodb.net, mode Atlas DNS SRV, Database orders, Authentication Username / password (SCRAM), alias mongo_atlas_app, Authentication database admin. The port is omitted and TLS is enabled automatically. Replace the sample hostname with the SRV hostname provided for your cluster.

Trust and authentication

Use the right Keystore entry

For a server certificate issued by a public CA trusted by the JVM, leave Trusted server certificate blank. For a private CA, import its certificate in Security → Keystore as a CERTIFICATE entry and select its alias. Kestrel uses that certificate as connection-scoped trust when opening the MongoDB client; it does not disable certificate verification. The selected alias is optional for TLS and is not a client certificate or a mutual-TLS key pair.

MongoDB username/password authentication uses SCRAM. A generic JWT credential is not a MongoDB login option in this form; MongoDB token authentication uses a distinct OIDC flow, which this connection does not currently expose.

Validation and troubleshooting

Interpret the connection test

A successful test proves that the configured host resolved, TLS and authentication succeeded, and ping completed against the database. It does not prove that the user can read or write every collection; test the required workflow action separately.

SymptomCheck
Credential alias unavailableCreate a User Credentials entry and select SCRAM authentication.

TLS certificate errorHostname matches the server certificate; choose the correct trusted CA certificate alias if using a private CA.
