Workflow / Connectors / Email

Send text, HTML, and attachments with Send Email.

Send Email uses a project Email (SMTP) connection. Its Step In document supplies the message, while Step Out reports that the SMTP server accepted it.

SMTP result ACCEPTED means the SMTP server accepted the message. It is not proof of final delivery to a mailbox.

Design

Create the connection, then configure the step

  1. 1
    Create an Email (SMTP) connection

    Follow the connection setup guide, test it, and leave it enabled.

  2. 2
    Add Send Email

    Drag the connector onto a workflow and connect it to the preceding and following steps.

  3. 3
    Select the connection

    Double-click Send Email and choose the project SMTP connection. A missing or disabled connection appears in workflow warnings.

  4. 4
    Map the message

    Open the settings icon. Map SendEmail_Request from Pipeline In to Step In; map SendEmail_Response from Step Out to Pipeline Out where later steps need it.

Step In

Build SendEmail_Request

Field under ${pipeline.input.SendEmail_Request}TypeRequirement and behavior
fromStringOne sender address. Optional when the connection has Default From.
to, cc, bccString eachAt least one recipient across these fields. Separate multiple addresses with commas, for example alice@example.com, bob@example.com.
replyToStringOptional; falls back to connection Default Reply-To. Multiple addresses can be comma separated.
subjectStringRequired, nonempty; encoded as UTF-8.
textBodyStringPlain-text alternative. Required if htmlBody is empty.
htmlBodyStringHTML alternative. Required if textBody is empty. When both are present, the email contains both MIME alternatives.
attachmentsDocumentListOptional list of file or inline image documents, described below.

Map each field from the pipeline or supply a deliberate constant. The SMTP connection controls transport; message-specific values belong in the pipeline.

MIME attachments

Attach documents and inline assets

Attachment fieldTypeBehavior
fileNameStringRequired filename, such as invoice.pdf.
contentTypeStringOptional MIME type; defaults to application/octet-stream.
contentBase64StringBase64 representation of file bytes. Preferred for files from webhook or Email Trigger.
contentString or bytesAlternative to Base64. String content is encoded as UTF-8.
contentIdStringOptional Content-ID for an inline image referenced by HTML, for example <img src="cid:logo">.

Use one document per attachment. PDF, DOCX, image, and other types are sent as MIME parts; no file conversion is performed. The connection maximum applies to both decoded content and final MIME size, which includes encoding overhead.

Step Out

Inspect SendEmail_Response

Field under ${pipeline.output.SendEmail_Response}TypeMeaning
statusStringACCEPTED when SMTP accepts the message.
messageIdStringGenerated email Message-ID.
recipientCountNumberTotal To, CC, and BCC recipients submitted.

Example

Send an HTML invoice with a PDF

{
  "SendEmail_Request": {
    "to": "buyer@example.com, accounts@example.com",
    "subject": "Invoice INV-1042",
    "textBody": "Your invoice is attached.",
    "htmlBody": "<p>Your <strong>invoice</strong> is attached.</p>",
    "attachments": [{
      "fileName": "invoice.pdf",
      "contentType": "application/pdf",
      "contentBase64": "JVBERi0xLjQ..."
    }]
  }
}

If this PDF came from a Webhook Trigger file, map its fileName, contentType, and contentBase64 into the attachment document.

Failure handling

Handle the precise send error

Invalid recipients, missing subject or body, missing or disabled connections, invalid Base64, message-size limits, authentication failures, and SMTP server errors throw SMTP_SEND_FAILED into workflow error handling with the specific failure message. Configure the Exception Handler path to log or process the failure. A send whose outcome is uncertain should not be retried blindly because the SMTP server may already have accepted it.
