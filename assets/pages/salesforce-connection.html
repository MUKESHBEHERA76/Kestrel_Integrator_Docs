Create a Salesforce connection.

A Salesforce Connection stores the login domain, REST API version, and a reference to a Security Credential. Both the Salesforce Trigger and Salesforce connector select an enabled connection in the same project.

Keep secrets in Security Credentials. The project connection references an alias; it does not ask for a password or private key.

Prerequisite

Create a matching Security Credential

Go to Security → Security Credentials and select Add security credential. Choose one of the supported OAuth types. Supply values issued for your Salesforce Connected App; the following domains and identifiers are examples, not working credentials.

TypeRequired fieldsExample and preparation
OAuth2 Client CredentialsToken service URL, Client ID, Client secrethttps://login.salesforce.com/services/oauth2/token, client ID from Connected App, its secret. Configure the Connected App for client credentials and a permitted run-as user. Optional client authentication, scope, audience, resource, and content type are available in the credential form.
OAuth2 JWT BearerToken service URL, Client ID, Salesforce username, Keystore key-pair aliasUse integration@example.com as an example username. First create or import an RSA key pair in Security → Keystore, configure its public certificate in the Connected App, then select that key-pair alias. The private key stays in Keystore.
OAuth2 Username-PasswordToken service URL, Client ID, Client secret, Salesforce username, PasswordAdd a security token when the org requires it. Use this flow only where the org permits it; authentication failures must be resolved in the Salesforce Connected App or user policy.

Use https://test.salesforce.com/services/oauth2/token for a sandbox when appropriate. The credential alias type must match the authentication type selected in the connection form.

Project setup

Create the reusable connection

  1. 1
    Open the project

    Go to Projects → your project → Connections → Create Connection and choose Salesforce Connection.

  2. 2
    Enter a name and login URL

    Example name: SalesforceProduction. Example login URL: https://login.salesforce.com; for a sandbox use https://test.salesforce.com. The URL must be an HTTPS Salesforce domain.

  3. 3
    Set the API version

    Enter a version in the form v61.0. Choose a version supported by your org and the operations you plan to use.

  4. 4
    Choose authentication and alias

    Select the same OAuth type as the Security Credential. The alias dropdown only shows credentials of that type. Select, for example, sf-production-jwt.

  5. 5
    Test, save, and enable

    Run Test Connection, save the connection, and leave it enabled so workflows can select it.

Verification

Understand what the test proves

Test Connection obtains an OAuth token and calls the Salesforce REST /services/data/{version}/limits endpoint. Success confirms authentication and basic REST API access. It does not prove access to every object, event channel, Apex endpoint, or Bulk API. For event access, use Check subscription in the Salesforce Trigger.

Troubleshooting

Resolve failures at the right layer

SymptomCheck
Credential alias does not appearConfirm the selected OAuth type matches the alias type and that the alias was saved.
Authentication failedCheck token URL, Connected App client ID/secret or JWT certificate, user access, and org policy.
Test succeeds but event trigger failsCheck the exact event channel, event permissions, and subscription result; the REST limits test does not subscribe.
Test succeeds but connector failsCheck the selected object or API permission and the operation error.
