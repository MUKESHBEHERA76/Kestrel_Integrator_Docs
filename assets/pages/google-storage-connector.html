Workflow / Connectors / Google Cloud Storage

Google Cloud Storage connector

Manage buckets, objects, and folder paths through Gcs_Request and Gcs_Response.

Folders and bucket names

In a standard bucket, folders are prefixes in object names: uploading invoices/2026/report.pdf makes the file appear under invoices/2026/. A hierarchical namespace bucket has real folder resources. Create Folder handles both kinds: it creates an empty marker object in a standard bucket and a folder resource in a hierarchical namespace bucket. Managed folders are separate IAM resources and are not created by this operation. See Google folder types.

Google does not rename an existing bucket. To change its name, create another bucket, copy objects and versions as required, verify the destination, update clients and workflows, then delete the old bucket. Update Bucket only changes supported metadata. See move data between buckets.

Configure and map the step

Go to Projects → your project → Workflows → open a workflow. Drag Google Cloud Storage from Connectors onto the canvas. Open the step and choose a tested, enabled Google Cloud Storage Connection and an Operation. The Operation changes the Step In fields under Gcs_Request. Open Pipeline settings and map those fields from the preceding step or hardcode a fixed example value. Map Gcs_Response fields to Pipeline Out for the next step, then save and run the workflow.

The project identifier and service key are stored in the connection. They are not pipeline fields. Every request input shown here is a String, including numeric text and JSON text. JSON string fields can contain pipeline variable substitutions before runtime parsing. The root Gcs_Request and Gcs_Response are Document containers grouping those String fields.

For Upload Object, map fileName and optionally folderPath; Kestrel joins them into the stored object name and URL-encodes it. The other object actions continue to use objectName to identify an existing object. Upload and download accept/return Base64 content, each limited to 10 MiB inline. For larger files, use a transfer design outside these inline operations.

Step Out fields

Step Out fieldMeaning
Gcs_Response.bodyComplete Google response as a JSON String for API actions; recursive delete returns a JSON summary here.
Gcs_Response.id, Gcs_Response.nameIdentifier and name when Google includes them in the top-level response.
Gcs_Response.nextPageTokenContinuation token for list actions; absent on the last page.
Gcs_Response.foldersJson, Gcs_Response.objectsJsonJSON String arrays from List Folder Contents. Parse them with JSON utilities if individual entries are needed.
Gcs_Response.deletedCount, Gcs_Response.failedObjectsJsonSuccessful recursive delete count as String and failures as a JSON String array. If deletion fails, the step raises an error and these outputs are not available downstream.

Operation examples

The following examples use illustrative values. Actual Google responses include additional fields. Operation details and IAM requirements: Google REST API reference.

Create bucket · CREATE_BUCKET

Step In: Gcs_Request fields: bucket, location; storageClass optional. Creates a project bucket; bucket names are globally unique.

Example mapped request:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "location": "US",
    "storageClass": "STANDARD"
  }
}

Illustrative Google response in Gcs_Response.body:

{
  "name": "acme-orders-archive",
  "location": "US"
}

Named Step Out: name; location. Most actions expose Gcs_Response.body as JSON text; Download object returns contentBase64 and sizeBytes instead. Fields appear only when present in the Google response.

Upload object · UPLOAD_OBJECT

Step In: bucket, fileName, and contentBase64 are required. folderPath and contentType are optional. The fileName must be one file name, without slashes. Kestrel stores the object as folderPath/fileName, or as fileName at the bucket root when folderPath is omitted. You do not map objectName for this action. Base64 encodes the raw bytes; inline uploads are limited to 10 MiB.

Example request: upload at bucket root:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "fileName": "1234.json",
    "contentBase64": "eyJwb2lkIjoiMTIzNCJ9",
    "contentType": "application/json"
  }
}

Illustrative Gcs_Response.body:

{
  "name": "1234.json",
  "size": "15"
}

Example request: upload inside a folder:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "folderPath": "orders/2026",
    "fileName": "1234.json",
    "contentBase64": "eyJwb2lkIjoiMTIzNCJ9",
    "contentType": "application/json"
  }
}

Illustrative Gcs_Response.body:

{
  "name": "orders/2026/1234.json",
  "size": "15"
}

Named Step Out: Gcs_Response.name is the complete stored path. On a standard bucket the folder is an object-name prefix; no Create Folder action is needed first. Google objects.insert.

Troubleshooting and limits

  • HTTP 401: check service account key validity in the connection.
  • HTTP 403: enable the API and grant the selected action’s IAM role on the target resource.
  • HTTP 404: verify project, bucket/dataset/topic, and item IDs. The connection target project determines the request project.
  • When using optional page tokens, pass Google’s returned nextPageToken into the next invocation. Stop when it is absent.
  • All Google API errors fail the step and can be inspected in workflow execution logs.

Create folder · CREATE_FOLDER

Step In: bucket and folderPath are required. Use a bucket-relative path; Kestrel adds the trailing slash. A standard bucket receives a zero-byte marker object. A hierarchical namespace bucket receives a real folder resource, with missing parents created. An existing standard-bucket marker causes a precondition failure.

Example request:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "folderPath": "invoices/2026"
  }
}

Illustrative Gcs_Response.body: the standard-bucket marker response is:

{
  "name": "invoices/2026/",
  "size": "0",
  "contentType": "application/x-directory"
}

For a hierarchical namespace bucket, the response is a folder resource with name: "invoices/2026/". In either case Gcs_Response.name is available. Folder creation is optional before uploading to a prefix in a standard bucket. Google folders.insert.

List folder contents · LIST_FOLDER_CONTENTS

Step In: bucket is required. Optional folderPath limits results to a folder; leave it blank for bucket root. recursive=false (default) returns immediate child folders and objects. recursive=true returns all matching objects and normally an empty folders array. Optional maxResults and pageToken control paging.

Example request:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "folderPath": "invoices",
    "recursive": "false",
    "maxResults": "100"
  }
}

Illustrative Gcs_Response.body:

{
  "prefixes": ["invoices/2026/"],
  "items": [{"name": "invoices/readme.txt"}],
  "nextPageToken": "NEXT_PAGE"
}

Named Step Out: foldersJson = "[\"invoices/2026/\"]", objectsJson = "[{\"name\":\"invoices/readme.txt\"}]", and nextPageToken = NEXT_PAGE. These are strings in the pipeline, not Document Lists. Repeat with the returned token until it is absent. The raw List Objects action remains available for direct prefix and delimiter control. Google objects.list.

Delete folder and contents · DELETE_FOLDER_RECURSIVE

Step In: bucket and folderPath are required; maxObjects is optional and defaults to 1000. The path is normalized to end in /, so invoices/2026 does not match invoices/20260. Kestrel lists matching object generations and, in hierarchical namespace buckets, nested folders before deleting. It fails without deleting anything if the object and folder count exceeds maxObjects. It deletes nested real folders deepest first after removing their objects.

Example request:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "folderPath": "invoices/2026",
    "maxObjects": "500"
  }
}

Successful Step Out:

Gcs_Response.body = {"deletedCount":2,"failedObjects":[],"completed":true}
Gcs_Response.deletedCount = "2"
Gcs_Response.failedObjectsJson = "[]"

A Google permission, retention, hold, or concurrent-change error can leave partial deletion. In that case the step fails and the error lists the affected objects; no successful Step Out is mapped. Each object delete uses a generation precondition. Google folders.delete · request preconditions.

Delete bucket and contents · DELETE_BUCKET_RECURSIVE

Step In: bucket is required; maxObjects is optional and defaults to 1000. Kestrel checks the count before deleting, removes object generations and hierarchical folders, then deletes the bucket. For an already empty bucket, use Delete Empty Bucket instead. This is a synchronous workflow step; keep the limit appropriate for the workflow timeout and use controlled batches for a large bucket.

Example request:

{
  "Gcs_Request": {
    "bucket": "acme-orders-archive",
    "maxObjects": "100"
  }
}

Successful Step Out after three object generations:

Gcs_Response.body = {"deletedCount":3,"failedObjects":[],"completed":true}
Gcs_Response.deletedCount = "3"
Gcs_Response.failedObjectsJson = "[]"

If bucket deletion fails after objects were removed, the step fails with a partial-deletion error. Retention, holds, managed folders, and soft delete policies still apply; this action cannot bypass Google protections or guarantee immediate permanent removal. Google bucket deletion.

Bucket naming and safety

Update Bucket cannot rename a bucket. To change the name, create a destination bucket, copy and verify data, update workflow mappings and clients, and delete the source bucket when safe. Do not treat Delete Bucket and Contents as a rename operation. Google bucket migration guide.

End-to-end object example

  1. Create the Cloud Storage connection and grant the service account permissions on the bucket.
  2. Map a webhook request's webHookRequest.body through a Base64 encoding utility into Gcs_Request.contentBase64. Set bucket = acme-orders-archive, folderPath = orders and fileName = ${pipeline.input.orderId}.json after extracting orderId from the webhook JSON into a runtime variable, and contentType = application/json.
  3. Choose Upload object. Map Gcs_Response.name to the next step or read the full metadata from Gcs_Response.body.
  4. For a download, use the same bucket and object name. Decode Gcs_Response.contentBase64 before treating the result as UTF-8 JSON or binary data.

Google references: objects.insert, objects.get, and Storage IAM roles.
