Security / Keystore

Manage certificates and cryptographic keys.

The tenant Keystore holds key pairs, certificates, SSH keys, RSA keys, and imported JKS or PKCS#12 entries. Integrations select entries by alias, keeping private material out of workflow configuration.

Setup

Add an entry to the tenant Keystore

  1. 1
    Open the page

    Go to Security → Keystore and click Add. The menu separates Create from Add operations.

  2. 2
    Choose an entry operation

    Generate a new Key Pair or SSH Key, or add an existing certificate, key, or keystore file. See the table below for accepted material.

  3. 3
    Give it an alias

    For single entries, use a descriptive alias such as sf-jwt-signing. It must start with a letter and use letters, numbers, dots, underscores, or hyphens. Whole-keystore import uses aliases from the file.

  4. 4
    Complete the form

    Enter generation settings, upload the file, or paste the supplied key as requested. Save, then confirm the entry appears in the Keystore table.

The generated Key Pair form offers RSA sizes 2048, 3072, and 4096 bits, or EC sizes 256 and 384 bits. Certificate validity accepts 1–3650 days. Match the algorithm to the consuming integration; Salesforce JWT Bearer requires RSA.

Worked example

Create a signing key for Salesforce JWT Bearer

  1. 1
    Generate

    Choose Add → Create → Key Pair. Set Alias sf-jwt-signing, Common Name integration.example.com, Key Algorithm RSA, Key Size 2048 (or larger), and Validity 365 days.

  2. 2
    Configure Salesforce

    Export the public certificate from the entry's actions and upload that certificate to the Salesforce Connected App's digital-signature configuration. Keep the private key in Kestrel.

  3. 3
    Reference it

    Create an OAuth2 JWT Bearer Security Credential and select sf-jwt-signing in the Keystore key-pair dropdown. Then select that credential in the Salesforce Connection and test it.

The key-pair dropdown only shows suitable Keystore entries; an EC key pair does not satisfy the Salesforce JWT credential's RSA validation.

Operations

Inspect and maintain entries

Select a row to view its metadata, certificate information, and available actions. The vertical three-dot menu offers actions appropriate to the entry type, including export, certificate-signing request, rename, update, or delete. Public certificates and keys can be shared where required; protect exported private material. Deleting or replacing an alias that a credential or connection uses can cause runtime authentication failures.

For a planned rotation, add the new entry first, update its public certificate at the remote system, change the consuming Security Credential to the new alias, test the connection, then retire the old entry.
