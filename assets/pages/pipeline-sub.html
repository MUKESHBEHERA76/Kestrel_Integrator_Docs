Pipeline Sub

Use pipeline values without hardcoding runtime data.

Pipeline substitution references a value by path using ${pipeline.scope.variable} syntax. The same syntax is available in Workflow Pipeline and Reusable Service Pipeline.

Basic syntax

Wrap the complete pipeline path in ${...}

The most common scopes are pipeline.input and pipeline.output.

ScopeExampleUse
pipeline.input${pipeline.input.customerId}Read a value entering the current step or service.
pipeline.output${pipeline.output.statusCode}Read a value produced by a step or stored for downstream use.
pipeline.temp${pipeline.temp.loopItem}Read a temporary runtime value such as the current loop item.
pipeline.system${pipeline.system.variableName}Read runtime-provided system data when that value exists.
pipeline.error${pipeline.error.errorMessage}Read error context made available during exception handling.
 
Exact value:
${pipeline.input.customerId}

Value inside text:
Customer ${pipeline.input.customerId} was created successfully.

An exact expression can retain the original runtime type. An expression embedded inside other text always produces a String.

Syntax by variable type

Use dots for document fields and indexes for list items

The examples use input scope. Replace input with output when the value is stored in pipeline output.

TypeExample structurePipeline substitution
String customerId = "C-1001" ${pipeline.input.customerId}
String List tags = ["priority", "new"] Whole list: ${pipeline.input.tags}
First string: ${pipeline.input.tags[0]}
Second string: ${pipeline.input.tags[1]}
Document customer = { name, address } Whole document: ${pipeline.input.customer}
Field: ${pipeline.input.customer.name}
Nested field: ${pipeline.input.customer.address.city}
Document List orders = [{ orderId, amount }] Whole list: ${pipeline.input.orders}
First document: ${pipeline.input.orders[0]}
Field in first document: ${pipeline.input.orders[0].orderId}
i
Lists use zero-based indexes

[0] means the first item, [1] means the second item, and so on. If the selected field is inside more than one list, each list level needs its own index.

Workflow Pipeline

Copy a variable path from the workflow mapper

You do not need to type long document paths manually.

  1. 1
    Open the step pipeline

    Select the workflow step and click its settings icon.

  2. 2
    Select a variable

    Click the required variable in Pipeline In, Step In, Step Out, or Pipeline Out.

  3. 3
    Click Copy

    The toolbar enables Copy after a variable is selected.

  4. 4
    Paste the expression

    Open the target field's hardcode editor and paste the copied pipeline syntax, then apply it.

Reusable Service Pipeline

Copy a variable path from the service mapper

The copy workflow is the same inside a reusable service.

  1. 1
    Open the reusable service

    Select the MAP or service step whose pipeline is visible.

  2. 2
    Select a pipeline variable

    Click the String, String List, Document, Document List, or nested field you need.

  3. 3
    Click Copy in the Pipeline toolbar

    Kestrel copies the normalized ${pipeline...} expression to the clipboard.

  4. 4
    Paste where substitution is supported

    Paste into a hardcoded value, connector input, utility input, message, URL, request body, or another supported String field.

!
Copy adds [0] for list paths

When you copy a list or a child inside a list, the editor creates a paste-ready path using the first item—for example, ${pipeline.input.orders[0].orderId}. Change the index if you need another fixed item. To pass the complete list, use the list root without [0], such as ${pipeline.input.orders}.

Important rules

Keep substitutions predictable

RuleCorrect exampleWhy
Use the complete braces${pipeline.input.name}This is the normalized syntax copied by both editors.
Use dots for document fields${pipeline.input.customer.name}Every dot moves to a child field.
Use brackets for list items${pipeline.input.orders[0]}The index chooses one list entry.
Use an exact expression for structured data${pipeline.input.orders}An exact expression can preserve a List or Document instead of converting it into display text.
Use embedded expressions only for textOrder ${pipeline.input.orderId} completedThe resolved value becomes part of one String.
Check the source scopeinput versus outputA valid path in the wrong scope resolves no value.
!
Do not substitute secrets into logs

Pipeline substitution can resolve passwords, tokens, and confidential documents. Map those values only into the connector input that requires them; do not place them in Logger or Pipeline Logger messages.
