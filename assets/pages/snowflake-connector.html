Run a Snowflake SQL statement from a workflow.

The Snowflake connector executes one SQL statement using an enabled project Snowflake connection. Map a query into queryString and read the row count and JSON response from the step output.

Step configuration

Configure the database step

  1. 1
    Prepare the connection

    Create and test a Snowflake connection in the same project. Keep it enabled.

  2. 2
    Add Snowflake

    Drag Snowflake from the workflow connector palette onto the canvas and connect it into the execution path.

  3. 3
    Select the project connection

    Double-click the connector and choose the saved Snowflake connection. Set Retry Count, Retry Interval in seconds, and optional Query Time Out in seconds. Retry Count 0 means one attempt.

  4. 4
    Map the query

    Open the connector pipeline settings and map the SQL string into ${pipeline.input.queryString}. Map the returned fields into the following step as needed. Save the mapping and workflow.

Pipeline contract

One input and two outputs

VariableTypeMeaning
${pipeline.input.queryString}StringOne SQL statement. Pipeline variable substitution is applied at runtime.
${pipeline.output.resultCount}StringRow count for a query, or update count for a statement.
${pipeline.output.dbResponse}StringSerialized JSON document containing resultList. Each row maps column labels to string values; SQL NULL becomes JSON null.

Only a single statement is accepted. For a result set, Kestrel reads all returned rows into resultList. For a statement without a result set, resultList is empty and resultCount reflects its update count.

Worked example

Look up a customer

Use connection SnowflakeAnalytics from the connection guide. Configure the step with Retry Count 1, Retry Interval 2 seconds, and Query Time Out 30 seconds. Map an appropriate SQL statement to queryString:

SELECT CUSTOMER_ID, STATUS
FROM ANALYTICS.PUBLIC.CUSTOMERS
WHERE CUSTOMER_ID = 'CUST-1042'

For one matching row, resultCount is "1" and dbResponse is a JSON string such as:

{"resultList":[{"CUSTOMER_ID":"CUST-1042","STATUS":"ACTIVE"}]}

Use a later transformation step if the next connector needs a structured document rather than a JSON string. Construct dynamic SQL carefully; runtime substitution inserts values into the query text and is not a prepared-statement parameter binding mechanism.

Execution

Timeout, retries, and connection use

Kestrel resolves the selected enabled connection from the current project, opens a pooled JDBC connection, activates the configured Snowflake session context, and executes the statement. Query Time Out is optional; when supplied, it must be a positive number of seconds. Retry Count and Retry Interval must be non-negative integers. Retry Count 2 permits up to three attempts.

Runtime Snowflake execution errors follow the retry settings. Configuration errors, a disabled connection, or a missing queryString fail without a query retry. A workflow Exception Handler can catch the resulting execution error.

Troubleshooting

Fix common Snowflake step failures

SymptomCheck
Connection not selectableCreate and enable a Snowflake connection in the same project.
queryString missingMap a non-empty SQL string into Step In.
Multiple statement errorSend one statement per connector step.
Authentication or session errorTest the Snowflake connection, its credential or key-pair alias, and session privileges.
