Workflow / Connectors / Salesforce

Call Salesforce from a workflow.

The Salesforce connector uses an enabled project Salesforce Connection to run a selected Salesforce API action. The workflow pipeline supplies request values and receives the HTTP response.

Design

Add a Salesforce step

  1. 1
    Prepare the connection

    Create and test an enabled Salesforce Connection in the same project.

  2. 2
    Place the connector

    Drag Salesforce from the workflow Connector tab onto the canvas and connect it in the execution path.

  3. 3
    Configure the action

    Double-click the step. Select Connection, API type, and Action. Supply an object API name, platform event API name, or Apex REST path when that action asks for one. Comment is optional.

  4. 4
    Map Step In and Step Out

    Open the settings icon. Map values to Salesforce_Request; map Salesforce_Response from Step Out to Pipeline Out when later steps need it. Changing API type or action resets the step's input contract, so review mappings after a change.

  5. 5
    Save and test

    Resolve workflow warnings, save, then run with test data. Use an Exception Handler for Salesforce or configuration failures.

Pipeline contract

Map request and response documents

All request fields live under ${pipeline.input.Salesforce_Request}. The editor generates only the fields needed for the chosen action. Use a source mapping or a deliberate constant. JSON object or list values supplied as body are serialized to JSON by the runtime; for Bulk CSV or Bulk XML, provide correctly formatted text for the selected action.

Step Out pathTypeMeaning
${pipeline.output.Salesforce_Response.statusCode}NumberSalesforce HTTP status, such as 201 for a created record.
${pipeline.output.Salesforce_Response.contentType}StringResponse Content-Type header, when supplied.
${pipeline.output.Salesforce_Response.body}Object or StringParsed JSON for JSON responses; raw text for CSV, XML, or other responses.

Step Out only becomes available to downstream pipeline paths according to mappings you save in the step settings. Do not map Pipeline In directly to Pipeline Out as a substitute for the connector result.

Worked examples

Start with a small REST operation

Create an Account: API type REST, Action Create record, Object API name Account. Set Salesforce_Request.body to a JSON document such as:

{
  "Name": "Acme Example Ltd",
  "Phone": "+1-415-555-0100"
}

The response body may contain a Salesforce record ID. Map Salesforce_Response.body.id or the returned body into a later step as appropriate for the actual response.

Query Accounts: API type REST, Action Query SOQL; map Salesforce_Request.query to SELECT Id, Name FROM Account LIMIT 10. Query does not require an Object API name field.

Publish a platform event: API type EVENT_PROCESSING, Action Publish platform event, API name Demo_Notification__e, and Salesforce_Request.body containing fields defined on that event, for example {"Message__c":"Order ready"}. This publishes a platform event, not a legacy Generic Event. To consume the event, configure a separate Salesforce Trigger for the same event API name.

Failure handling

Route failures through the workflow

A missing or disabled connection, invalid object/path/ID, missing required request field, authentication failure, and non-2xx Salesforce response fail the step and are available to the workflow's Exception Handler. The message includes the API type, action, HTTP status, and a safe Salesforce error when available. A 401 response causes one token refresh and retry. Review the effect of retrying create, publish, or bulk operations because a remote request may have succeeded before Kestrel observed a response.

The connection's Test Connection verifies authentication and REST limits access only. An operation can still fail because the connected Salesforce user lacks object, field, event, Apex, or Bulk API permission.
