What MAP Pipeline does

Control the data shape between service steps

MAP Pipeline is a flow step for data movement. It does not call an external system and does not start a service.

Use it when the current pipeline does not have the exact names or structure required by the next utility, project service, or final service output.

Use MAP Pipeline forExample
Rename a value by mapping it to another path${pipeline.input.id} → ${pipeline.output.customerId}
Build a new document from several source fieldsMap name, email, and phone into an output customer document.
Pass a complete list or one selected itemMap all order lines, or only lines[0].
Assign a fixed or substituted valueSet source to WEB_PORTAL or use ${pipeline.input.requestId}.
Create a value needed by later stepsAdd a runtime output variable named normalizedOrder.
Remove unwanted pipeline dataDrop a large raw request after creating the smaller output document.
i
Mapping and transformation are different

MAP Pipeline moves and structures values. For calculations, formatting, parsing, concatenation, JSON/XML conversion, or date logic, add the appropriate utility before or after the MAP step and map its inputs and outputs.

Add a MAP step

Open it from the reusable service Flow tab

  1. 1
    Open the reusable service

    Define Service I/O first so the required input and output fields are available in the mapper.

  2. 2
    Select Flow

    Find Map pipeline in the left step library.

  3. 3
    Add the step

    Click it or drag it into the required position in the flow tree.

  4. 4
    Select Map pipeline

    The Pipeline panel displays the variables available before the step and the fields that can receive values.

  5. 5
    Create mappings

    Drag a source field from Pipeline In and drop it onto a compatible field in Pipeline Out.

Every saved mapping is shown as a line. Select a mapping line to delete it. Indexed mappings can be double-clicked to edit their list-index settings.

Real use case

Normalize a webhook order for shared processing

A workflow receives a provider-specific order and calls a reusable service named normalizeOrder. The service must return one stable document used by billing and fulfillment.

Service input

{
  "requestId": "REQ-9001",
  "rawOrder": {
    "id": "ORD-1042",
    "customer": {
      "email": "developer@example.com"
    },
    "items": [
      { "sku": "KB-10", "quantity": 2 },
      { "sku": "MS-20", "quantity": 1 }
    ]
  }
}

MAP Pipeline mappings

Pipeline InPipeline OutOperation
${pipeline.input.rawOrder.id}${pipeline.output.normalizedOrder.orderId}Copy the provider order ID into the stable field name.
${pipeline.input.rawOrder.customer.email}${pipeline.output.normalizedOrder.customerEmail}Flatten the nested customer email.
${pipeline.input.rawOrder.items}${pipeline.output.normalizedOrder.lines}Choose Map whole list in Index Mapping.
${pipeline.input.requestId}${pipeline.output.normalizedOrder.correlationId}Retain the caller's correlation value.
Hardcoded value WEB_PORTAL${pipeline.output.normalizedOrder.source}Identify the source system.

Service output

{
  "normalizedOrder": {
    "orderId": "ORD-1042",
    "customerEmail": "developer@example.com",
    "lines": [
      { "sku": "KB-10", "quantity": 2 },
      { "sku": "MS-20", "quantity": 1 }
    ],
    "correlationId": "REQ-9001",
    "source": "WEB_PORTAL"
  }
}

After creating the normalized document, the service can Drop ${pipeline.input.rawOrder} if later steps no longer need the provider payload.

!
Indexes are zero-based and must resolve to non-negative integers

An index outside the source-list size causes a mapping error. Validate externally supplied indexes before using them.

Hardcoded target values

Assign constants or pipeline substitutions

Double-click a Pipeline Out target to open its type-aware hardcode editor.

  • String — enter plain text or a substitution such as ${pipeline.input.requestId}.
  • String List — add one row per list item.
  • Document — enter values for its defined child fields.
  • Document List — add one or more document entries and populate their fields.
  • Boolean — select true or false.
  • Other complex lists — enter a valid JSON value.

Use Pipeline Sub for complete substitution syntax and the Copy workflow.

Runtime variables

Create a target that is not already in Service I/O

Runtime variables are useful for intermediate results needed only inside the service.

  1. 1
    Click Runtime variable

    Open the variable editor from the MAP Pipeline toolbar.

  2. 2
    Enter a unique name and type

    Choose String, String List, Document, Document List, or another supported type.

  3. 3
    Define structure when required

    Add child fields for Documents or select a project Data Structure reference.

  4. 4
    Add the variable

    It appears under ${pipeline.output.variableName} and can receive mappings or hardcoded values.

Add final caller-facing values to Service I/O Output. Use runtime variables for internal intermediate data.

Good practices

Keep mappings readable and maintainable

  • Define Service I/O before building mappings so final target paths remain stable.
  • Use one MAP step for one clear reshaping responsibility.
  • Prefer explicit mappings over carrying an entire raw request through every step.
  • Use utilities for calculations and format conversion instead of treating MAP as executable code.
  • Map whole lists only when source and target element structures are compatible.
  • Name runtime variables by business meaning, such as normalizedOrder, not temp1.
  • Drop large or sensitive values when downstream steps no longer require them.
  • Run the reusable service with empty, normal, and multi-item list inputs before publishing changes to callers.
