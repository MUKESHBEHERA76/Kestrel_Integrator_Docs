Create a named cache

Configure the storage and limits

  1. 1
    Open Administration → Cache Manager → Cache

    An Administrator creates a cache once. Any project can then use its name in a Cache utility.

  2. 2
    Choose New cache

    Enter a unique name, such as customerProfiles, and a description. Names start with a letter and contain up to 80 letters, digits, underscores, or hyphens. The name cannot be changed after creation.

  3. 3
    Choose the backend

    Use Local memory for one server or data that can differ between servers. Choose Shared Redis for cross-server reads and writes, then select a Redis connection profile from the Redis Connection tab.

  4. 4
    Set lifetime and capacity

    Set default TTL, maximum entries, maximum value bytes, and local memory bytes. Defaults are 600 seconds, 10,000 entries, 262,144 bytes per value, and 67,108,864 local-memory bytes. Maximum entries and local-memory bytes bound the local-memory backend; Redis capacity and eviction are controlled by the Redis server.

  5. 5
    Enable and save

    The cache is immediately available by its name to Cache utilities in both editors. Disabled caches reject runtime access.

SettingAllowed valueExample
Default TTL1–31,536,000 seconds900 (15 minutes)
Maximum entries1–1,000,000; enforced for local memory10000
Maximum value size1,024–10,485,760 bytes262144 (256 KiB)
Local memory limit1,048,576–2,147,483,648 bytes; enforced for local memory67108864 (64 MiB)

Every entry has a TTL. Local memory evicts least recently used entries when its entry or byte limit is exceeded, and is lost when the server restarts. Redis entries also expire, but Redis server memory and eviction policy apply. See Redis's key expiration guide and eviction guide.

Shared Redis

Create and verify a Redis connection

Redis connection profiles in Cache Manager are platform-wide and distinct from the Redis configuration used for internal Kestrel coordination.

  1. 1
    Prepare Redis

    Use a Redis endpoint reachable from every Kestrel server. Grant the application account access to the selected database and the commands needed for reads, writes, TTL, PING, and inspection. Use a stable service endpoint or proxy if the Redis deployment has failover. Review Redis's security guidance.

  2. 2
    Open Redis Connection → New connection

    Enter a name, host, port (1–65535), and database number (0–15). For example: SharedRedisProd, redis.internal.example, 6380, database 2. Enter an ACL username and password if the server requires them. Passwords are encrypted at rest and are not returned by the management API.

  3. 3
    Configure TLS if required

    Turn on Use TLS and use the server's TLS port. For a public CA, leave the certificate alias empty to use system trusted CAs. For a private CA, upload its trusted X.509 certificate in Security → Keystore, then select its alias. The alias validates the Redis server certificate; it does not provide a client certificate for mutual TLS. See Redis's TLS configuration guide.

  4. 4
    Test before saving

    Click Test connection in the form. A successful test completes a Redis PING and shows a success dialog. A failure shows a connection error without saving the profile. You can test an existing profile from its card menu. For an edited profile, a blank password field reuses the saved password. Redis documents PING.

  5. 5
    Save and select

    Save the Redis connection, then create a cache with backend Shared Redis and select this profile. A Redis connection cannot be deleted while a cache references it.

i
Real deployment example

For two Kestrel workers behind a load balancer, configure both to reach redis.internal.example:6380 over TLS. Create one Redis connection profile and one customerProfiles cache. A value written by a workflow on worker A can be read by a reusable service on worker B.

Workflow and reusable-service Utils

Map cache inputs and outputs in the pipeline

Add a Cache operation from Utils → Cache in either editor. Map pipeline values into Step In / Service In, then map Step Out / Service Out to the desired Pipeline Out fields.

UtilityInputsNormal outputMeaning
cache:putcacheName String, key String, value Object, optional ttlSeconds Stringstored=true BooleanWrite or replace an entry and its TTL.
cache:putIfAbsentSame as putstored=true if written; false if a live key existsDo not overwrite a live entry. The conditional write is atomic within the chosen backend.
cache:getcacheName String, key Stringfound Boolean and value ObjectA miss returns found=false, value=null.
cache:containsKeycacheName, keyfound BooleanCheck presence without returning the value.
cache:removecacheName, keyremoved BooleanDelete one entry; missing key returns false.

cacheName identifies a platform cache, not a project KVS. key must contain 1–512 characters. value may be a JSON-compatible String, number, Boolean, Document, or Document List, but cannot be null. An omitted or blank ttlSeconds uses the cache default; otherwise it must be an integer from 1 to 31,536,000. Check found before using the value returned by cache:get.

Worked integration

Cache a customer profile for 15 minutes

A customer API workflow fetches account C-1042 from the system of record. It maps the response Document to cache:put.value, and the key to customer:C-1042. A separate order workflow can retrieve that value through the same cache name.

cache:put input
cacheName = customerProfiles
key = customer:C-1042
value = {"customerId":"C-1042","tier":"Gold","region":"APAC"}
ttlSeconds = 900

cache:put output
stored = true

cache:get input
cacheName = customerProfiles
key = customer:C-1042

cache:get output before expiry
found = true
value = {"customerId":"C-1042","tier":"Gold","region":"APAC"}

cache:get output after expiry or eviction
found = false
value = null

Map cache:get.found to an IF condition. On a miss, fetch the current profile from the source API and repopulate the cache. This is a cache-aside pattern; the cache is not the source of truth.

After a customer update, call cache:remove with the same name and key. Its output is removed=true when the entry existed, or false when it was already absent. For an idempotent initialization, use cache:putIfAbsent; its stored=false result means another live value was retained.

Administration

Inspect and maintain entries

ActionEffect
Search and filtersFind caches by name, description, or Redis connection; filter by backend and enabled state.
InfoView configuration, entry count, stored value bytes, available local memory, and per-server hit/miss/write counters. Redis server-wide free space is not shown as cache-specific capacity.
Browse entriesRead-only key and value preview, with key search. At most 100 entries are returned; values above 4 KB are shortened. Redis inspection stops after 10,000 scanned keys and marks partial results.
ClearRemove entries after confirmation. Local memory clear affects the server handling the request. Redis clear rotates the cache namespace; other Kestrel servers refresh the definition within about one second.
Disable / EnableDisabled caches reject runtime utility access. Existing data may remain until it expires or is cleared.
Edit / DeleteBoth require confirmation. Deleting a cache removes its definition and clears its entries. A Redis connection cannot be deleted while referenced by a cache.

Cache keys and values can contain sensitive business data. Administrators with Browse entries access can inspect them. Avoid storing secrets, and use the shortest practical TTL.
