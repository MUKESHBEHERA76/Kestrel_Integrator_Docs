CSV Parser

Parse delimited text into row documents or build CSV text from a DocumentList. No external connection is required.

Configuration

Choose Parse or Build

Add CSV Parser in the workflow Connector tab, double-click it, choose Parse or Build, and set Column delimiter (default comma), Row delimiter (runtime line separator), Quote character (default double quote), and optional field names. Set Quote all when generating CSV if every cell must be quoted. Open Settings to map Step In and Step Out.

Parse mode

Convert CSV text to CsvList

Map a String to ${pipeline.input.csvContent}. With no configured fields, the first row supplies column names. With configured fields, a matching first row is treated as a header; otherwise the first row is data. Values remain strings. Missing cells become empty strings; surplus cells become fieldN.

csvContent = id,name,status
1042,Asha,ACTIVE
1043,Ravi,PENDING

Output ${pipeline.output.CsvList} is a DocumentList:

[{"id":"1042","name":"Asha","status":"ACTIVE"},{"id":"1043","name":"Ravi","status":"PENDING"}]

Build mode

Convert documents to CSV text

Map a DocumentList to ${pipeline.input.docList}. Define fields for a stable column order; otherwise the first document’s keys become the header. Kestrel escapes embedded quote characters and quotes cells containing the delimiter or a line break.

docList = [{"id":"1042","name":"Asha"},{"id":"1043","name":"Ravi"}]
csvString = id,name
1042,Asha
1043,Ravi

The String result is placed in ${pipeline.output.csvString} and ${pipeline.output.outCSV}. A configured target path also receives the value. Parse mode can likewise use a configured target instead of the default CsvList.

Runtime notes

Handle source format explicitly

Match the delimiter and quote settings to the sender. The parser does not validate field types or a business schema; add a validation step after parsing. For binary file input, decode the file to text first. Large CSV content is materialized in memory, so use bounded payload sizes.
