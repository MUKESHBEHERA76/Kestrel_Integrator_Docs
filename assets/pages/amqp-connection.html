Projects / Connections / AMQP

Connect to an AMQP 0-9-1 broker.

Create a project AMQP connection for the AMQP Trigger or AMQP workflow connector. This connection speaks AMQP 0-9-1, commonly used by RabbitMQ. It is not interchangeable with AMQP 1.0.

↔

Connection vs destination The connection stores broker transport and authentication. The workflow trigger names the existing queue to consume.

Before you begin

Collect broker details

Ask the broker administrator for a reachable host and port, virtual host, user credentials, an existing queue, and permission to consume from that queue. Kestrel does not create broker queues or bindings. If TLS is required, import the trusted server certificate under Security → Keystore first; select its alias in the connection. For client-certificate authentication, also import a client key pair.

Create

Configure the connection in the project

  1. 1
    Choose AMQP

    Open Projects → your project → Connections → Create Connection and choose AMQP. Give it a descriptive connection name.

  2. 2
    Set the broker endpoint

    Select a provider profile (Generic AMQP 0-9-1, RabbitMQ, CloudAMQP, Amazon MQ for RabbitMQ, or Custom). Enter Host and Port. Optionally enter a client connection name and additional failover endpoints, one host:port per line.

  3. 3
    Set transport and authentication

    Choose TLS and an appropriate authentication method. TLS requires a trusted server certificate alias. PLAIN requires username/password; EXTERNAL requires TLS and a client key-pair alias; OAuth 2.0 requires token URL, client ID, and client secret. Anonymous is available when the broker permits it.

  4. 4
    Set the AMQP 0-9-1 session

    Enter the existing virtual host, heartbeat in seconds, requested channel limit, and topology recovery setting. The virtual host is required.

  5. 5
    Test and save

    Use Test Connection to verify network reachability, AMQP 0-9-1 handshake, authentication, and TLS where configured. Save and keep the connection enabled before selecting it in a workflow.

A successful connection test confirms broker login; it does not prove that the trigger's queue exists or that this account may consume it. Test the workflow with a real message too.

SymptomCheck

Authentication or virtual-host errorCredentials, broker permissions, and exact virtual-host name.
TLS handshake failsTrusted server certificate alias, certificate chain, hostname, and broker TLS port.
