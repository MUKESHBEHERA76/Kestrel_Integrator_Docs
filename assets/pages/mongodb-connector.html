Workflow design

Add and configure the MongoDB step

  1. 1
    Prepare the project connection

    Create and test a MongoDB Connection in the same project. Keep it enabled.

  2. 2
    Place the connector

    Drag MongoDB from the workflow Connector tab onto the canvas. Double-click it and select the project connection, an operation, and a collection name such as employees.

  3. 3
    Map Step In

    Open the step settings. Map the operation's fields beneath MongoDB_Request from Pipeline In or constants. filter, document, and update are String fields containing JSON objects; documents and pipeline are String fields containing JSON arrays of objects. The connector parses the JSON at runtime.

  4. 4
    Map Step Out and save

    Map the needed MongoDB_Response fields into Pipeline Out for later steps, save the mapping, and resolve workflow warnings. Run with a small test dataset before enabling writes.

Pipeline contract

Understand request and response fields

Step In uses ${pipeline.input.MongoDB_Request}. The editor shows the fields for the selected action. Step Out uses ${pipeline.output.MongoDB_Response}; map values onward only when downstream steps need them. The runtime initializes all response fields on every action, so inspect the fields meaningful for that action in the tables below.

Response fieldTypeMeaning
acknowledgedString (true/false)Write acknowledgement for insert, update, replace, and delete. Read actions initialize it to true; it is not a read result.
documentsString (JSON array)Results from Find one, Find many, or Aggregate. Find one returns zero or one list item.
matchedCountString (decimal number)Matches for update/replace, or document count for Count.
modifiedCountString (decimal number)Documents changed by update or replace.
deletedCountString (decimal number)Documents removed by Delete one or Delete many.
insertedIdsStringListIDs generated for inserts or an upsert. An ObjectId is rendered as a hex string.

Other fields retain their initialized values: documents is the JSON string [], insertedIds is an empty StringList, and counts are the string 0. Documents use MongoDB JSON serialization; for an ObjectId field, inspect the returned document shape before mapping it as a plain string.

Type example: MongoDB_Request.filter = {"employeeId":"${pipeline.input.webHookRequest.body.employeeId}"} is one String whose contents become a MongoDB filter at runtime. MongoDB_Response.acknowledged is the String true; counts are Strings such as 42; documents is a JSON array String such as [{"employeeId":"E-1001"}]; insertedIds remains a StringList, with one ID per item. JSON fields are not Data Structure document references.

Read operations

Find, count, and aggregate

OperationStep In exampleMeaningful Step Out
Find onefilter = {"employeeId":"E-1001"}. An empty filter {} matches the first document.documents = [{"employeeId":"E-1001","name":"Ada"}] or [] if none matched.
Find manyfilter = {"department":"Engineering"}; limit = 25.documents contains up to 25 matching documents.
Count documentsfilter = {"isActive":true}. Use {} to count the collection.matchedCount = 42, for example.
Aggregatepipeline = [{"$match":{"department":"Engineering"}},{"$group":{"_id":"$department","total":{"$sum":1}}}]; limit = 100.documents = [{"_id":"Engineering","total":42}], for example.

limit defaults to 100 and accepts 1–1000 for Find many and Aggregate. The runtime appends a limit stage to aggregation. Aggregation stages containing $out or $merge are rejected; use an explicit write action. Find one, Find many, and Count can use an empty filter, though the editor may still show the filter field for mapping.

Insert operations

Create one or many documents

OperationStep In exampleMeaningful Step Out
Insert onedocument = {"employeeId":"E-1001","name":"Ada","isActive":true}acknowledged = true; insertedIds = ["507f1f77bcf86cd799439011"], for example.
Insert manydocuments = [{"employeeId":"E-1002","name":"Ben"},{"employeeId":"E-1003","name":"Chen"}]acknowledged = true; insertedIds contains one ID per inserted document.

Map a String containing a nonempty JSON object for Insert one and a String containing a nonempty JSON array of objects for Insert many. If your document supplies _id, MongoDB uses it subject to collection rules; otherwise the driver can generate one. A duplicate key fails the step and is available to the workflow Exception Handler.

Update operations

Change fields or replace a document

OperationStep In exampleMeaningful Step Out
Update onefilter = {"employeeId":"E-1001"}; update = {"$set":{"department":"Platform"}}; upsert = false.matchedCount = 1; modifiedCount = 1. An upsert ID appears in insertedIds.
Update manyfilter = {"department":"Engineering"}; update = {"$set":{"reviewRequired":true}}; upsert = false.matchedCount and modifiedCount report affected document counts; insertedIds contains an upsert ID if created.
Replace onefilter = {"employeeId":"E-1001"}; document = {"employeeId":"E-1001","name":"Ada","department":"Platform"}; upsert = false.matchedCount, modifiedCount, and optional upsert insertedIds.

Update requires a nonempty filter and an update object containing an operator such as $set. Replace requires a nonempty filter and replacement document; it replaces the matched document's fields instead of applying update operators. Map upsert to true only when creating a document on no match is intended; omitted or false disables upsert. A match can have modifiedCount = 0 when the stored value already equals the requested value.

Delete operations

Use an explicit filter

OperationStep In exampleMeaningful Step Out
Delete onefilter = {"employeeId":"E-1001"}acknowledged and deletedCount = 1 when one document was removed.
Delete manyfilter = {"status":"ARCHIVED"}acknowledged and deletedCount = number removed.

The runtime requires a nonempty filter for both delete actions. It rejects {} so a missing mapping cannot delete the whole collection. Delete many removes every document matching the supplied nonempty filter; review it carefully before enabling the workflow.

Developer walkthrough

Read a webhook employee and update MongoDB

Suppose a Webhook Trigger receives {"employeeId":"E-1001","department":"Platform"}. Add a MongoDB step using connection MongoOrders, collection employees, and operation Update one. Map MongoDB_Request.filter to {"employeeId":"E-1001"} and MongoDB_Request.update to {"$set":{"department":"Platform"}}; in a real flow, build those objects from the webhook values. Map MongoDB_Response.matchedCount and modifiedCount into Pipeline Out or a following response step. A zero matchedCount means no employee matched; it does not by itself fail the workflow.

Runtime behavior

Handle validation and database failures

A missing or disabled project connection, invalid collection name, malformed JSON input, empty write filter, rejected aggregation stage, credential failure, timeout, or MongoDB server error fails the step with a MongoDB error message. Connect an Exception Handler to handle the failure. No automatic retry or transaction boundary across multiple workflow steps is promised by this connector.

For find operations, an empty result list is a successful run. For update and delete, zero affected documents is also a successful driver result; branch on the response counts when your business process needs to treat that as an error.
