Google Cloud Storage connection

Store the target project and service account identity once; use the connection from Google Cloud Storage workflow steps.

Prerequisites and IAM

Enable the relevant Google API in the target project: storage.googleapis.com. Storage Admin (roles/storage.admin) at project level for bucket creation/deletion/update and object operations; for an existing bucket used only for object work, grant Storage Object Admin (roles/storage.objectAdmin) on that bucket instead. Listing all buckets is a project-level permission. Review Google's IAM roles reference before granting access.

Start with the Google Cloud service account setup for exact Console steps, JSON key creation, API enablement, and key security.

Create, test, and use

  1. Open Projects → your project → Connections → Create Connection → Google Cloud Storage Connection.
  2. Set connection name to google-storage-prod, Project identifier to acme-integrations-prod, Service account email to kestrel-gcp@acme-integrations-prod.iam.gserviceaccount.com, then paste the complete JSON key.
  3. Click Test connection. A successful result means OAuth authentication succeeded. It does not prove the action-specific IAM role or that the API is enabled.
  4. Create the connection and keep it enabled. In the workflow connector, select google-storage-prod and map operation inputs.

Key handling: Kestrel encrypts the saved key server-side. It is never shown again in View or Edit. Leave the key field blank in Edit to keep it, or paste a new JSON key to rotate. Keep the downloaded file out of repositories and shared logs. If Google blocks key creation through iam.disableServiceAccountKeyCreation, ask your Google Cloud administrator; this Kestrel connection currently requires a JSON service account key and does not provide Workload Identity Federation.

Troubleshooting

ResultWhat to check
Invalid JSON or email mismatchPaste the complete downloaded JSON; compare client_email with the email field.
OAuth rejects the keyCheck revoked key, server time, outbound HTTPS to oauth2.googleapis.com, and service account status.
Test succeeds; operation returns HTTP 403Grant the operation’s IAM permission on the target project, bucket, dataset, topic, or subscription. Authentication and authorization are separate.
API disabled / HTTP 403Enable storage.googleapis.com in APIs & Services for the project.
