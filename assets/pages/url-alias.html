Administration / URL Alias

Give a webhook a short URL.

An alias is an optional, platform-wide short path for one webhook workflow. The original workflow endpoint remains available.

Create and invoke an alias

  1. Open Administration → URL Alias as an Administrator and select Create New Alias.
  2. Search the Webhook workflow picker by project or workflow name and select the target.
  3. Enter an alias such as orders; review the URL preview and create it.
  4. Call the short URL with the workflow's configured HTTP method, authentication, headers, query parameters, and body.
Alias: orders
Workflow: Sales / SubmitOrder
Method: POST
Short URL: http://127.0.0.1:8080/api/triggers/a/orders

curl -X POST 'http://127.0.0.1:8080/api/triggers/a/orders?source=partner' \
  -H 'Content-Type: application/json' \
  -H 'X-Correlation-ID: demo-1042' \
  -d '{"orderId":"1042"}'

Replace the host, method, headers, and body with your deployment and workflow settings. The alias invokes the same webhook workflow; see Webhook Trigger and Webhook Auth for request configuration.

Rules and maintenance

Aliases are lowercase and unique across the platform. Use 1–100 letters, digits, underscores, or hyphens; the first character must be a letter or digit. Search or filter existing aliases by project and enabled status. Use Copy URL, Enable/Disable, or Delete on each alias. Deletion asks for confirmation.

A duplicate alias returns a conflict. An invalid alias or workflow selection is rejected. A missing, disabled, or orphaned alias returns HTTP 404. Disabling an alias does not disable its original webhook URL.
