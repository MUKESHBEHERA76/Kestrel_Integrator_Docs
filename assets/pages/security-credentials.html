Security / Security Credentials

Store integration credentials by alias.

Security Credentials stores typed, reusable credential records for project connections and workflow steps. The form changes with the credential type; secret fields are encrypted and masked in views.

Common procedure

Create and use a credential

  1. 1
    Open the registry

    Go to Security → Security Credentials and select Add security credential.

  2. 2
    Name and classify it

    Use a unique alias such as sf-production-jwt. The name starts with a letter and may contain letters, numbers, dots, underscores, or hyphens. Select the credential type before entering its fields. Add a description that identifies the system and owner.

  3. 3
    Fill required fields

    Use the table below. Example hosts, users, IDs, and secrets in this guide are placeholders; replace them with your provider's values. Save with Store credential.

  4. 4
    Select the alias

    Open the consuming project connection or workflow step and choose the matching credential alias. For Salesforce, the connection dropdown is filtered by OAuth type.

The list supports search and type filtering. Credential type cannot be changed after creation; create a new alias when the authentication method changes.

Required fields are enforced on save. URL fields accept HTTP or HTTPS at the credential layer; use HTTPS for remote OAuth providers. Provider-specific permissions and token policies are checked when the consuming integration actually connects.

Worked example

Prepare Salesforce JWT Bearer credentials

  1. 1
    Create the signing key

    In Security → Keystore, choose Add → Create → Key Pair. Use alias sf-jwt-signing, algorithm RSA, key size 2048 or greater, and a suitable certificate validity. Export its public certificate and configure that certificate on the Salesforce Connected App.

  2. 2
    Create the credential

    Select OAuth2 JWT Bearer. Enter alias sf-production-jwt, token URL https://login.salesforce.com/services/oauth2/token, Connected App Client ID, Salesforce username integration@example.com, and Keystore key-pair alias sf-jwt-signing. Store it.

  3. 3
    Create the connection

    Follow the Salesforce Connection guide. Choose OAuth2 JWT Bearer and select sf-production-jwt from the filtered alias dropdown. Run Test Connection.

Kestrel reads the private key from Keystore at runtime to sign the assertion. Do not paste a PEM private key into Security Credentials. A sandbox may use https://test.salesforce.com/services/oauth2/token and the corresponding sandbox login URL.

Operations

Update, rotate, and retire aliases

Use the vertical three-dot menu to edit or delete. Secret values are masked when viewed. During an edit, leave a masked secret field blank to retain its existing encrypted value; enter a new value to rotate it. The alias type remains fixed. A deleted credential can break integrations that reference it, so update the consuming connection or workflow before deletion.

Credential status describes the saved credential record. A STORED status is not a live connectivity test. Test the consuming connection, for example Salesforce Connection → Test Connection, after changing credentials.
