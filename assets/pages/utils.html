JSON utilities

Convert between JSON array text and Document Lists

json:documentListToJSON serializes a Document List into one JSON array String. json:jsonArrayToDocumentList parses JSON array text into a native Document List. Both utilities are available under Utils → JSON in workflows and reusable services.

JSON array String to Document List

Suppose an HTTP step returns the following body as a String. Map that String to jsonString in the utility's Step In or Service In:

[
  {
    "employeeId": "EMP-1001",
    "name": "John Doe",
    "department": "Engineering",
    "active": true,
    "skills": ["Java", "SQL"]
  },
  {
    "employeeId": "EMP-1002",
    "name": "Sarah Connor",
    "department": "DevOps",
    "active": false,
    "skills": ["Linux"]
  }
]

After execution, documentList in Step Out or Service Out contains two native documents. Map it to a Document List Pipeline Out variable, for example employees, or to the next step. The first item has employeeId = EMP-1001, active = true, and a skills list containing Java and SQL. The second item has active = false. Booleans and arrays remain typed values; the result is not a JSON String.

StepPathType
Input${service.input.jsonString}String containing a JSON array; a native Document List is also accepted
Output${service.output.documentList}Document List

For multipart webhook uploads, webHookRequest.body and webHookRequest.attachments already contain a native list of file documents. Map attachments directly to a Document List destination. If it is mapped into jsonString, the utility validates the items and passes the list through.

[] produces an empty Document List. Empty or malformed JSON, an object instead of an array, or an array containing a scalar or null raises UTILITY_ERROR. See the complete utility reference for the mapping contract and runtime notes.

Date utilities

Generate and format Unix epoch time

Both operations are available under Utils → Date in workflows and reusable services. date:getCurrentEpochTime reads the server clock without input. date:epochTimeToDateTime formats an epoch value using a Java DateTimeFormatter pattern. Both inputs and outputs appear as Strings in the pipeline editor.

UtilityStep In / Service InStep Out / Service Out
date:getCurrentEpochTimeNo inputsepochTime (String): current Unix seconds
date:epochTimeToDateTimeepochTime (String), targetDateTimeFormat (String)outputDate (String): formatted UTC time

Example: chain both utilities

  1. 1
    Read the current time

    Add date:getCurrentEpochTime. It has no Step In fields. Map ${service.output.epochTime} to a String variable such as currentEpoch in Pipeline Out.

  2. 2
    Format the timestamp

    Add date:epochTimeToDateTime. Map currentEpoch to ${service.input.epochTime} and hardcode targetDateTimeFormat as yyyy-MM-dd HH:mm:ss. Map ${service.output.outputDate} to the next step or a String Pipeline Out variable.

For a repeatable example, epochTime = 0 and targetDateTimeFormat = yyyy-MM-dd HH:mm:ss produce outputDate = 1970-01-01 00:00:00. The 13-digit millisecond input 1704067200000 produces 2024-01-01 00:00:00 with the same pattern. The formatter always uses UTC; include XXX in the pattern when the output should show the Z offset. Epoch values of other lengths are interpreted as seconds.

These operations do not change the workflow or service pipeline automatically. Map their outputs to Pipeline Out or another step. A missing or non-integer epochTime, a missing or invalid pattern, or an out-of-range value fails the conversion step with UTILITY_ERROR.

List utilities

Group documents by criteria

list:groupDocuments is available under Utils → List in workflows and reusable services. It follows the input names of webMethods pub.document:groupDocuments. Kestrel gives each result group explicit fields for easy pipeline mapping.

SideFieldTypePurpose
InputdocumentsDocument ListRecords to group
InputgroupCriteria[]Document ListOne or more criteria with required key and optional compareStringsAs, pattern
OutputdocumentGroups[]Document ListEach item has groupValues (Document), documents (Document List), and count (String)
documents = [
  {"id":"1","team":"A"},
  {"id":"2","team":"B"},
  {"id":"3","team":"A"}
]
groupCriteria = [{"key":"team"}]

documentGroups = [
  {"groupValues":{"team":"A"},"documents":[{"id":"1","team":"A"},{"id":"3","team":"A"}],"count":"2"},
  {"groupValues":{"team":"B"},"documents":[{"id":"2","team":"B"}],"count":"1"}
]

Map source records to ${service.input.documents}, criteria to ${service.input.groupCriteria}, and ${service.output.documentGroups} to a Document List pipeline variable. Add multiple criteria to group by their combined values. A key can address a nested Document using address.city or address/city. Groups follow the first matching document; members keep source order. Documents missing any grouping key share a single group with empty groupValues.

compareStringsAs defaults to string; use numeric to group 1.0 with 1.00, or datetime with a required Java date/time pattern. Empty documents returns an empty group list. Invalid inputs raise UTILITY_ERROR. The input list and documents are not modified.

List utilities

Search a Document List using field pairs

list:searchDocumentList is available under Utils → List in workflows and reusable services. Its fieldList input is a Document List containing fieldName and fieldValue String fields, similar to the header pair list in Send HttpResponse.

SideFieldTypePurpose
Step In / Service IndocumentListDocument ListSource records to search
Step In / Service InfieldList[]Document ListOne or more {fieldName, fieldValue} pairs
Step Out / Service OutdocumentListDocument ListMatching records, including an empty list when none match

Example: match two fields

documentList = [
  {"employeeId":"EMP-1001","department":"Engineering","active":true},
  {"employeeId":"EMP-1002","department":"DevOps","active":false},
  {"employeeId":"EMP-1003","department":"Engineering","active":true}
]
fieldList = [
  {"fieldName":"department","fieldValue":"Engineering"},
  {"fieldName":"active","fieldValue":"true"}
]

// Step Out / Service Out
documentList = [
  {"employeeId":"EMP-1001","department":"Engineering","active":true},
  {"employeeId":"EMP-1003","department":"Engineering","active":true}
]

Map the input list to ${service.input.documentList} and the criteria list to ${service.input.fieldList}. Map ${service.output.documentList} to a Document List Pipeline Out variable. All criteria must match the same document. Results retain source order; there is no limit of one result. A missing field never matches. For nested fields, use a dotted name such as address.city. Names and values match case-sensitively; booleans and numbers in source documents are compared to the String form supplied in fieldValue.

The utility does not change the input documents. An empty source list returns an empty result. An empty fieldList, missing input, invalid pair, or non-document source item raises UTILITY_ERROR.

Failure behavior

Invalid utility input fails the step

  • Unsupported operations, invalid numbers, malformed JSON/XML, invalid dates, and invalid time zones raise a runtime utility error.
  • A utility error stops the normal branch unless an enclosing TRY/CATCH handles it.
  • Do not log KVS secrets, decoded credentials, tokens, or confidential documents while troubleshooting.
  • Use the exact types shown in each utility contract; apparent scalar values are frequently represented as Strings in the pipeline editor.
