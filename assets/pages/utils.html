Utilities perform focused transformations, calculations, lookups, and flow operations. Select a utility from the nested menu for its exact inputs, outputs, data types, runtime behavior, example, and failure notes.

Add and configure

Select Utils, then map the operation

  1. 1
    Open the Utils palette

    In Workflow or Reusable Service, select the Utils tab and add the required operation.

  2. 2
    Open its pipeline

    Select the utility step to view its typed Step In/Service In and Step Out/Service Out contract.

  3. 3
    Map or hardcode inputs

    Connect pipeline values to required inputs. Optional inputs may be omitted when the documented default is suitable.

  4. 4
    Map outputs explicitly

    Connect only the outputs needed by downstream steps. Utility output is not automatically copied to Pipeline Out.

  5. 5
    Test edge cases

    Test empty values, invalid formats, list boundaries, time zones, and failure handling before deployment.

JSON utilities

Convert between JSON array text and Document Lists

json:documentListToJSON serializes a Document List into one JSON array String. json:jsonArrayToDocumentList parses JSON array text into a native Document List. Both utilities are available under Utils → JSON in workflows and reusable services.

JSON array String to Document List

Suppose an HTTP step returns the following body as a String. Map that String to jsonString in the utility's Step In or Service In:

[
  {
    "employeeId": "EMP-1001",
    "name": "John Doe",
    "department": "Engineering",
    "active": true,
    "skills": ["Java", "SQL"]
  },
  {
    "employeeId": "EMP-1002",
    "name": "Sarah Connor",
    "department": "DevOps",
    "active": false,
    "skills": ["Linux"]
  }
]

After execution, documentList in Step Out or Service Out contains two native documents. Map it to a Document List Pipeline Out variable, for example employees, or to the next step. The first item has employeeId = EMP-1001, active = true, and a skills list containing Java and SQL. The second item has active = false. Booleans and arrays remain typed values; the result is not a JSON String.

StepPathType
Input${service.input.jsonString}String containing a JSON array; a native Document List is also accepted
Output${service.output.documentList}Document List

For multipart webhook uploads, webHookRequest.body and webHookRequest.attachments already contain a native list of file documents. Map attachments directly to a Document List destination. If it is mapped into jsonString, the utility validates the items and passes the list through.

[] produces an empty Document List. Empty or malformed JSON, an object instead of an array, or an array containing a scalar or null raises UTILITY_ERROR. See the complete utility reference for the mapping contract and runtime notes.

Failure behavior

Invalid utility input fails the step

  • Unsupported operations, invalid numbers, malformed JSON/XML, invalid dates, and invalid time zones raise a runtime utility error.
  • A utility error stops the normal branch unless an enclosing TRY/CATCH handles it.
  • Do not log KVS secrets, decoded credentials, tokens, or confidential documents while troubleshooting.
  • Use the exact types shown in each utility contract; apparent scalar values are frequently represented as Strings in the pipeline editor.
