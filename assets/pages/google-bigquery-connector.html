Workflow / Connectors / Google BigQuery

Google BigQuery connector

Choose one of 11 operations, map BigQuery_Request inputs, and use BigQuery_Response outputs downstream.

Configure and map the step

Go to Projects → your project → Workflows → open a workflow. Drag Google BigQuery from Connectors onto the canvas. Open the step and choose a tested, enabled Google BigQuery Connection and an Operation. The Operation changes the Step In fields under BigQuery_Request. Open Pipeline settings and map those fields from the preceding step or hardcode a fixed example value. Map BigQuery_Response fields to Pipeline Out for the next step, then save and run the workflow.

The project identifier and service key are stored in the connection. They are not pipeline fields. Every request input shown here is a String, including numeric text and JSON text. JSON string fields can contain pipeline variable substitutions before runtime parsing. The root BigQuery_Request and BigQuery_Response are Document containers grouping those String fields.

Execute SQL uses Standard SQL. An unfinished query returns a job reference; map jobId and location to Get query results. Load from Cloud Storage starts a job and does not wait for completion. Map the returned job reference to Get job and check status.state and status.errorResult in body. Insert rows checks insertErrors even when Google returns HTTP 200.

Operation examples

The following examples use illustrative values. Actual Google responses include additional fields. Operation details and IAM requirements: Google REST API reference.

Execute SQL · EXECUTE_SQL

Step In: BigQuery_Request fields: sql; location, parametersJson, maximumBytesBilled optional. Standard SQL. For parametersJson supply a JSON array of BigQuery query parameter objects.

Example mapped request:

{
  "BigQuery_Request": {
    "sql": "SELECT order_id, total FROM `acme-integrations-prod.sales.orders` LIMIT 10",
    "location": "US"
  }
}

Illustrative Google response in BigQuery_Response.body:

{
  "jobReference": {
    "jobId": "job_123",
    "location": "US"
  },
  "jobComplete": true,
  "rows": [
    {
      "f": [
        {
          "v": "1234"
        },
        {
          "v": "49.95"
        }
      ]
    }
  ]
}

Named Step Out: jobId; location; jobComplete. All actions expose BigQuery_Response.body as JSON text. Fields appear only when present in the Google response.

Load from Cloud Storage · LOAD_FROM_GCS

Step In: BigQuery_Request fields: datasetId, tableId, sourceUri; sourceFormat, autodetect, writeDisposition optional. Starts an asynchronous load job. Poll Get job until DONE and inspect status.errorResult. Supported source format is passed to Google; CSV is the default.

Example mapped request:

{
  "BigQuery_Request": {
    "datasetId": "sales",
    "tableId": "orders",
    "sourceUri": "gs://acme-orders-archive/orders.csv",
    "sourceFormat": "CSV",
    "autodetect": "true",
    "writeDisposition": "WRITE_APPEND"
  }
}

Illustrative Google response in BigQuery_Response.body:

{
  "jobReference": {
    "jobId": "load_123",
    "location": "US"
  },
  "status": {
    "state": "PENDING"
  }
}

Named Step Out: jobId; location. All actions expose BigQuery_Response.body as JSON text. Fields appear only when present in the Google response.

Troubleshooting and limits

  • HTTP 401: check service account key validity in the connection.
  • HTTP 403: enable the API and grant the selected action’s IAM role on the target resource.
  • HTTP 404: verify project, bucket/dataset/topic, and item IDs. The connection target project determines the request project.
  • When using optional page tokens, pass Google’s returned nextPageToken into the next invocation. Stop when it is absent.
  • All Google API errors fail the step and can be inspected in workflow execution logs.

Parameterized query and load example

For a dynamic SQL value, use a BigQuery query parameter rather than concatenating untrusted input into SQL. Map BigQuery_Request.sql to SELECT order_id FROM `acme-integrations-prod.sales.orders` WHERE order_id = @orderId and BigQuery_Request.parametersJson to this JSON String:

[
  {"name":"orderId","parameterType":{"type":"STRING"},"parameterValue":{"value":"1234"}}
]

The value can be replaced with a pipeline variable expression before runtime JSON parsing. For a file load, first upload a file to gs://acme-orders-archive/orders.csv, then choose Load from Cloud Storage with sourceUri set to that URI, sourceFormat = CSV, autodetect = true, and writeDisposition = WRITE_APPEND. Map the returned jobId and location into Get job until status.state is DONE. A DONE job can still contain status.errorResult.
