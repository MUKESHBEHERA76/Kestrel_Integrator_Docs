Workflow / Connectors / Google BigQuery

Google BigQuery connector

Choose one of 11 operations, map BigQuery_Request inputs, and use BigQuery_Response outputs downstream.

Configure and map the step

Go to Projects → your project → Workflows → open a workflow. Drag Google BigQuery from Connectors onto the canvas. Open the step and choose a tested, enabled Google BigQuery Connection and an Operation. The Operation changes the Step In fields under BigQuery_Request. Open Pipeline settings and map those fields from the preceding step or hardcode a fixed example value. Map BigQuery_Response fields to Pipeline Out for the next step, then save and run the workflow.

The project identifier and service key are stored in the connection. They are not pipeline fields. Every request input shown here is a String, including numeric text, boolean text, and JSON text. JSON string fields can contain pipeline variable substitutions before runtime parsing. The root BigQuery_Request and BigQuery_Response are Document containers grouping those String fields.

Execute SQL uses GoogleSQL. An unfinished query returns a job reference; map jobId and location to Get query results. Load from Cloud Storage starts a job and does not wait for completion. Map the returned job reference to Get job and check status.state and status.errorResult in body. Insert rows checks insertErrors even when Google returns HTTP 200.

Step Out fields

Step Out fieldMeaning
BigQuery_Response.bodyComplete Google response serialized to a JSON String; parse it when a nested field is needed.
BigQuery_Response.id, BigQuery_Response.nameTop-level identifiers when Google returns them.
BigQuery_Response.jobId, BigQuery_Response.locationBigQuery job reference, including nested jobReference values, when returned.
BigQuery_Response.pageToken, BigQuery_Response.totalRows, BigQuery_Response.jobCompleteQuery result paging token, total row count, and completion state when returned. The completion state is String text (true or false). BigQuery normally returns pageToken, which you map back to the request pageToken.

Troubleshooting and limits

  • HTTP 401: check service account key validity in the connection.
  • HTTP 403: enable the API and grant the selected action’s IAM role on the target resource.
  • HTTP 404: verify the configured project, dataset, table, or job ID. The connection target project determines the request project.
  • For query results, table rows, datasets, and tables, map Google’s returned pageToken to the next request’s pageToken. Stop when the response has no token.
  • All Google API errors fail the step and can be inspected in workflow execution logs.

Parameterized query and load example

For a dynamic SQL value, use a BigQuery query parameter rather than concatenating untrusted input into SQL. The connector determines NAMED or POSITIONAL mode from whether every parameter in parametersJson has a name; mixing both forms fails before the request is sent. Map BigQuery_Request.sql to SELECT order_id FROM `acme-integrations-prod.sales.orders` WHERE order_id = @orderId and BigQuery_Request.parametersJson to this JSON String:

[
  {"name":"orderId","parameterType":{"type":"STRING"},"parameterValue":{"value":"1234"}}
]

The value can be replaced with a pipeline variable expression before runtime JSON parsing. For a file load, first upload a file to gs://acme-orders-archive/orders.csv, then choose Load from Cloud Storage with sourceUri set to that URI, sourceFormat = CSV, autodetect = true, and writeDisposition = WRITE_APPEND. Map the returned jobId and location into Get job until status.state is DONE. A DONE job can still contain status.errorResult.
