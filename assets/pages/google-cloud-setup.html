Google Cloud service account setup

Prepare one service account and grant only the permissions required by your Cloud Storage, BigQuery, or Pub/Sub workflows.

Step by step

Example target project: acme-integrations-prod; example service account: kestrel-gcp@acme-integrations-prod.iam.gserviceaccount.com. Replace both with your real identifiers. The service account can live in another project if it is granted the required roles on the target project or resource.

  1. 1
    Select the target Google Cloud project.

    In Google Cloud Console use the project selector. Copy its Project ID, not its display name or project number. Enable the APIs you plan to use under APIs & Services → Library: Cloud Storage JSON API, BigQuery API, or Cloud Pub/Sub API.

  2. 2
    Create the identity.

    Open IAM & Admin → Service Accounts → Create service account. Enter an ID such as kestrel-gcp, create it, and copy the resulting email. Google can take about a minute to propagate a new service account.

  3. 3
    Grant service permissions.

    Open IAM & Admin → IAM → Grant access. Enter the service account email as the principal and choose the smallest roles for the operations you will use. For BigQuery, grant dataset access separately where appropriate. See each connection guide for example roles. The operator who grants roles needs IAM permission to change policy; the service account itself does not need IAM administrator access.

  4. 4
    Create a JSON key if your organization permits it.

    Open the service account → Keys → Add key → Create new key → JSON. Google downloads the file once. Open it locally and paste the whole JSON object into Kestrel's Service key JSON field. Do not paste only private_key. The client_email in the file must match the form's service account email, and token_uri must be https://oauth2.googleapis.com/token.

  5. 5
    Test and save in Kestrel.

    In Projects → your project → Connections → Create Connection, choose the relevant Google connection type, enter the fields, click Test connection, then Create Connection. Test connection validates the key and obtains a Google OAuth token. It does not check whether Storage, BigQuery, or Pub/Sub permits a particular action; run a workflow operation to check IAM.

Google references: Create service accounts; Create JSON service account keys; Grant IAM roles; Enable APIs; Service account OAuth flow.

Key handling: Kestrel encrypts the saved key server-side. It is never shown again in View or Edit. Leave the key field blank in Edit to keep it, or paste a new JSON key to rotate. Keep the downloaded file out of repositories and shared logs. If Google blocks key creation through iam.disableServiceAccountKeyCreation, ask your Google Cloud administrator; this Kestrel connection currently requires a JSON service account key and does not provide Workload Identity Federation.

Example key shape

{
  "type": "service_account",
  "project_id": "acme-integrations-prod",
  "private_key_id": "KEY_ID_FROM_GOOGLE",
  "private_key": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n",
  "client_email": "kestrel-gcp@acme-integrations-prod.iam.gserviceaccount.com",
  "token_uri": "https://oauth2.googleapis.com/token"
}

This is only a shape example. Use the exact, complete JSON downloaded from Google. A fabricated key cannot authenticate.
